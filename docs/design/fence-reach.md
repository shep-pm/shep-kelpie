# Fence: what a call reaches

The hosts a sandbox reaches beyond GitHub and the model. What a worker may write and run is in
fence.md, what it reads (dependency sources included) in fence-reads.md.

- Hosts: `allowed_domains`, and always the registries of the package managers the call's worktree keeps a lockfile or manifest for, in its root or a folder directly under it: npm and pnpm `registry.npmjs.org`, yarn `registry.yarnpkg.com` and `registry.npmjs.org`, bun `registry.npmjs.org`, cargo `crates.io`, `index.crates.io` and `static.crates.io`, go `proxy.golang.org` and `sum.golang.org`, uv and pip `pypi.org` and `files.pythonhosted.org`. One table, `crates/core/src/package_managers/mod.rs`, also gives the dev server's install its lockfiles, commands and caches and `doctor`'s `package registries` line its managers (`runner/dev_server/install/`, `src/doctor/registries.rs`). Only a call that works an item gets them (`Runner::worker_reach`); reviewers and the other roles keep `allowed_domains`. `crates/core/src/profile/mod.rs`
- Caches: a call that works an item also gets the cache variables of the same managers, each a folder of its build folder (`GOCACHE` and `GOMODCACHE`, `NPM_CONFIG_CACHE`, pnpm's store, cache, state and lock folders, `YARN_CACHE_FOLDER`, `BUN_INSTALL_CACHE_DIR`, `UV_CACHE_DIR`, `PIP_CACHE_DIR`), since each tool writes its cache on every run and the home's is denied. The table is their one source: the dev server's install and its server take the same ones (`package_managers::caches`, `Worker::build_env_in`), and a project no longer writes them in `build_env`. A project's own `build_env` entry wins over the table's, and only `GOLANGCI_LINT_CACHE` stays fixed in the profile. Names are uppercase, since `build_env`'s are: `NPM_CONFIG_CACHE` and `NPM_CONFIG_STORE_DIR` are read as the lowercase names were (npm does, as the npm fixture shows). Older pnpm is assumed to read `NPM_CONFIG_STORE_DIR` as it read the lowercase name; no run has measured it. A worktree's files choose which rows apply, except the caches a tool writes on every build and install, which every worker gets (`GOCACHE`, `BUN_INSTALL_CACHE_DIR`, pnpm's `PNPM_CONFIG_*` and `XDG_RUNTIME_DIR`, `package_managers::always_caches`): a project with no lockfile yet, or one below the folders detection reads, runs its first install or build in the fence too (the maintainer's ruling on #1733's review). The rest, such as `GOMODCACHE`, whose home copy is read, only follow detection. #1706, `crates/core/src/settings/mod.rs`, `runner/turn/mod.rs`, `runner/dev_server/mod.rs`
