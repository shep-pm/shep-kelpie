# Agent allow list

Which agents a project may use. The agent settings are in agents.md, the agent file in agent-files.md.

- `agents.allow` (optional list of agent names; absent or `[]` allows every agent with a file, `Allow::holds` is true for an empty list): the only agents the project may use, for a private project that keeps its code to the models its owner names. `find` in `crates/core/src/settings/agents/mod.rs` refuses a name the list leaves out, naming the setting that holds it and `agents.allow`, for each `agents.implementers` entry, `agents.pm`, `agents.representative`, `triage.agent`, `contributions.security_reviewer` and each listed or default reviewer (`agents.reviewers`, `contributions.reviewers`; a default one names `agents.reviewers` as the other fix). `Runner::implementer_files` returns only the implementer files it holds, so an `agent:` label names an allowed implementer or is skipped as `LabelError::NoAgent`, labels are made only for them, and they are the agents an agent board ask carries. `Runner::worker_agent` fails the turn of an open work item whose agent the list now leaves out, saying to add it or drop and add the issue. Names are not checked against the agents folder, since files are reread each wake: a missing file is refused where the name is used. `fallback_after` and the default implementer need nothing, since every listed implementer passed the check. A reread takes a change to `allow` or `slack` alone (`runner/reread/mod.rs`). `upgrade` and `settings migrate` write no `allow` (a test pins it). A file in `agents/` whose name starts with `_` is ignored as if absent: `Agents::load` lists it in `ignored()` and not `skipped`, `snapshot` leaves it out, and `doctor` names them in one `agent files` line (`doctor/ignored.rs`), so every reader (runner, dog, doctor, verbs) agrees. Such a file was skipped with a log line, since a name has no `_`; now it is ignored quietly. It does not switch off a shipped agent, whose embedded copy and stub stay.
