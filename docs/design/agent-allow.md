# Agent allow list

Which agents a project may use. The agent settings are in agents.md, the agent file in agent-files.md.

- `agents.allow` (optional list of agent names; absent or `[]` allows every agent with a file, `Allow::holds` is true for an empty list): the only agents the project may use, for a private project that keeps its code to the models its owner names. `find` in `crates/core/src/settings/agents/mod.rs` refuses a name the list leaves out, naming the setting that holds it and `agents.allow`, for `agents.pm`, `agents.representative`, `triage.agent`, `contributions.security_reviewer` and each reviewer a contribution reads (`contributions.reviewers`, or kelpie's default pass when it names none, which names `contributions.reviewers` as the other fix). It is also a review pass's lineup: every reviewer file it holds is a candidate but `contributions.security_reviewer`, and a project naming no agent is held to none of its candidates (`Settings::lineup`, `Settings::names_reviewers`, `settings/reviewers/mod.rs`). `Settings::allowed_implementers` returns only the implementer files it holds, so an `agent:` label names an allowed implementer or is skipped as `LabelError::NoAgent`, labels are made only for them, and they are the agents an agent board ask carries. `Runner::worker_agent` fails the turn of an open work item whose agent the list now leaves out, saying to add it or drop and add the issue. Names are not checked against the agents folder, since files are reread each wake: a missing file is refused where the name is used. A reread takes a change to `allow` or `slack` alone (`runner/reread/mod.rs`). `upgrade` and `settings migrate` write no `allow` except the one case that adds to a list: a project whose `allow` is already a non-empty list gets each name its `agents.reviewers` held added to it, each once, and `agents.reviewers` is then deleted and named with the value it held, as the keys in `GONE_KEYS` are (`src/flock/set/migrate.rs`, a test pins each). The same run writes those names, each once, into `contributions.reviewers` when the project names none there: a contribution's pass reads that key and not `agents.reviewers`, so a project with a listed `allow` would otherwise fall to kelpie's default contribution reviewers, which that `allow` refuses, and its runner would not open. An absent or empty `allow` stays as it is: every reviewer file is allowed already, and a list of reviewers alone would refuse every implementer. `add` writes no `reviewers` at all, and `agents init` prints no `shep kelpie set agents.reviewers` line. A file in `agents/` whose name starts with `_` is ignored as if absent: `Agents::load` lists it in `ignored()` and not `skipped`, `snapshot` leaves it out, and `doctor` names them in one `agent files` line (`doctor/ignored.rs`), so every reader (runner, dog, doctor, verbs) agrees. Such a file was skipped with a log line, since a name has no `_`; now it is ignored quietly. It does not switch off a shipped agent, whose embedded copy and stub stay. Slice 2 of #1378; cut 5 made it the implementers' only list and removed `implementers`, `implementer_choice` and `fallback_after`, and #1544 made it the reviewers' only list and removed `agents.reviewers`. The four removed keys load unread (`Gone`): doctor names them, `upgrade` deletes them.
