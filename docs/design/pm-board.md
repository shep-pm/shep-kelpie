# Project manager's board

The board file, `board.md`, the project manager reads: what it holds, how it is written, what it shows of each call. The agent's wakes and answers are in pm.md, and its cases in [pm-case.md](pm-case.md).

- Runner writes `board.md` so PM never runs git or gh (code-written board decides as well). Keeps newest 50 events + PM cursor; issue bodies quoted (600 chars) behind `> `; text naming this machine withheld. #326, `runner/briefing/`
- Each wake carries the whole board in its prompt, under a heading after the reasons, and `board.md` holds the same text. The whole board, not a delta: relative ages ("opened 8h46m ago") change on every item line between wakes, so a board diff is noise, and the events section is already the delta. A board past 64 KiB is left out and the Read instruction stays, since the prompt is one argv argument. #989, `runner/pm/prompt/`
- `board.md` has an Agents section after the ready queue: the implementers the agent board may pick, by name, then its reviewers in their order, each with its tier, its kinds (`every kind` when the file sets none) and its description (`no description` when it has none). It reads each `Agent.fit` from the book at each write, so a file edit shows at the next one and no model name reaches it. An implementer's line carries `; starts now|<date_time> UTC, typically <elapsed>, <cost>` from the dog's reading (`AgentLine::reading`), or `; no reading from the board`; a reviewer's carries neither (agent-board-runner.md). `<cost>` names the pick's budget (`Pick::budget`, agent-board.md), or keeps `about $<cost>|costs nothing (local model)|cost unknown` when the pick names none. An agent that is out carries `; out until <date_time> UTC: <why>` after that (`AgentLine::out`). The opening says the project manager names each item's agent, kelpie takes the cheapest available that fits when it names none, an `agent:<name>!` label pins, and a wait for an agent is a hold (ADR 0020). After the bullets, one plain line per plan account the listed agents spend (`Runner::plan_lines`: `agent_limit` over `board_agents` and `lineup`, in `Account` order; a local model, gateway or API agent adds none) reads `Claude week: 16% used, 14% of the week gone, 6d 1h to the reset, on course for 114%, read 4m ago`: used and read age from `Runner::pacing`'s `Assessment::reading`, elapsed share (`pacer::week_gone_pct`, rounded) and time to the reset from the clock at the write, and the course from `pacer::week_end_pct` (`used * 100 / gone`), left out while the elapsed share is 0. An account nothing has paced reads `Claude week: no reading`, and one whose week resets at or before now reads `the reading predates the week's reset, read <age> ago`; Codex the same way. The opening adds that a plan's week is a budget to spend by its reset, not to save: read the pace and where it lands, not the share left; under 100% run more items at once and give work that holds up other work to the faster plan agent; over 100% lean on local models; a small share left near the reset is no reason to slow down. It gives one rule per budget in place of one order: a local model first when it can take the item, the API credit and the plan week to their pace, the one further behind its reset first, and billed API only as overflow, for a named or pinned agent alone (agent-board.md). The pace lines say how far down each budget to reach when its agents are busy, and a short ready queue is no reason to spend faster. No setting is added. #1910. `Runner::agent_lines` fills it from what the runner holds, with no new read: a review bot's lease window while closed (`window_opens`, shared with the review lineup; why "its review window is closed"), else the hold the pacer last found on the agent's plan account (`Runner::last_hold`: a spent 5-hour window or a spent week, whichever lasts longer, its `until` later than now, whatever the reading's age; its `why` the hold's reason), else none. #1378, #1425, `core/board/briefing/`, `runner/briefing/`
- The plan lines' writer adds one API credit line after them, from `Briefing::credit`, asked by `Runner::read_agents` beside the `reading` ask and kept as long. It reads `API credit: 40% used, 23% of the month gone, 23d to the reset, on course for 174%`: used is `spent_usd` over `monthly_usd`, uncapped, gone is `since` to now over the month, and the course is `pacer::week_end_pct` as the plan lines use it, left out while gone is 0. No read age: the dog's figure is fresh. No line while `api.monthly_credit_usd` is unset, the dog cannot be reached, or `resets_at` is not after now; it shows with no plan account listed. Its opening gains a paragraph, only with the line: the credit is a bonus on the plans, paced across the month so its course aims at 100% by its end, the share left then is lost, so under 100% put more work on API agents and over 100% put less by naming a plan agent, and a standing note to spend it freely until a date sets the pacing aside (agent-board-api.md). No setting (ADR 0020). #1921, `core/board/briefing/plans.rs`
- A green run's log is not in a case: the project manager asks for it with `run_log` (`item`, `run`; the run on the item's `## CI` list), and the next wake carries it. The case is pm-case.md, the wake and its held ruling pm.md. #1813
- Worker silent 10 min reads as idle (PM told only "busy" misses a hung worker). #326
- A ready issue's line carries `; unblocks #a, #b` between its `waits` part and its `names` part when other ready issues have it as an open blocker: lowest first, the first `UNBLOCKS_LISTED` (5) named and the rest `N more`. `unblocked_by` in `runner/briefing/` inverts `ReadyIssue::blocked_by` over `ready_in_order`, which holds the links `link_blockers` completed from `Blocked by:` lines, so no forge call is added and `Runner::skipped` is not read (the pass stops at the first issue it can take). Only ready issues without a work item are named, and only direct dependents. The opening adds that an issue whose line says `unblocks` holds up other work. #1909, `core/board/briefing/`, `runner/briefing/`
- A call that has not had its gateway lease is never idle or stuck: quiet counts from the grant, and a wait past 10 min is its own wake, not a stuck item. Only a wait for a lease names the lease holder; a gateway that answered busy named no client as the cause, and the board names what the call waits for, and what it got, in the same words the wake uses. #964, `runner/briefing/`, `runner/flight/`
- Overlap from `git diff` + `git merge-tree` (git 2.38+), cached by commit, run without runner lock (trigger never waits on git). A head conflicting with `main` is a `Behind main` line, and those files are out of its pairs. #326, #1318
- Each wake writes `settings/<project>.toml` for every project on this shepherd, this one included, after emptying `settings/` so a removed project leaves nothing. `pm_reach` denies the agent kelpie's homes, so a copy is how it reads a project's setup. The tables are those the runner's last look read: `read_tables_with` keeps every sheep's `[app.dogs.kelpie]` table beside its own (`Tables.others`) and `Look` hands them to `Runner.peer_tables` with no new request, so the copy is as fresh as the runner's settings; this project's own entry is the table the runner took, so a refused or unloadable table is not shown, while the others still follow the shepherd. `shown_table` drops any key whose name holds `token`, `secret`, `password` or `credential` at any depth (a table inside an array too), and an `env` or `*_env` table keeps its names with the values hidden (`worker.build_env` among them); a `*_env` or `*_var` key holding a string names a variable and stays. Every string then goes through `shown`, so a path naming this machine reads `(withheld: ...)`. Kelpie's `[kelpie]` section (the webhook's URL, the TOTP settings) is never written. The copy is never read back, so an edit changes nothing, and the `## Code` line says so. A file that cannot be written is named on that line and in the log. Every project is open to every project manager on the shepherd, each the maintainer's own. #1815, `runner/pm/peers.rs`, `core/settings/peers.rs`
