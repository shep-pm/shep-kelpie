# Project manager's board

The board file, `board.md`, the project manager reads: what it holds, how it is written, what it shows of each call. The agent's wakes and answers are in pm.md.

- Runner writes `board.md` so PM never runs git or gh (code-written board decides as well). Keeps newest 50 events + PM cursor; issue bodies quoted (600 chars) behind `> `; text naming this machine withheld. #326, `runner/briefing/`
- Each wake carries the whole board in its prompt, under a heading after the reasons, and `board.md` holds the same text. The whole board, not a delta: relative ages ("opened 8h46m ago") change on every item line between wakes, so a board diff is noise, and the events section is already the delta. A board past 64 KiB is left out and the Read instruction stays, since the prompt is one argv argument. #989, `runner/pm/prompt/`
- `board.md` has an Agents section after the ready queue: the implementers the agent board may pick, by name, then its reviewers in their order, each with its tier, its kinds (`every kind` when the file sets none) and its description (`no description` when it has none). It reads each `Agent.fit` from the book at each write, so an edit to a file shows at the next one, and no model name reaches it. An implementer's line carries `; starts now|<date_time> UTC, typically <elapsed>, about $<cost>|costs nothing (local model)|cost unknown` from the dog's reading (`AgentLine::reading`), or `; no reading from the board`; a reviewer's carries neither (agent-board-runner.md). An agent that is out carries `; out until <date_time> UTC: <why>` after that (`AgentLine::out`). The section's opening says the project manager names each item's agent, kelpie takes the cheapest available that fits when it names none, an `agent:<name>!` label pins, and a wait for an agent is a hold (ADR 0020). `Runner::agent_lines` fills it from what the runner holds, with no new read: a review bot's lease window while closed (`window_opens`, shared with the review lineup; why "its review window is closed"), else the `Scope::Dispatch` hold (a spent 5-hour window or a spent week, whichever lasts longer) the pacer last found on the agent's plan account (`Runner::last_hold`, whatever the reading's age, while its `until` is later than now; why the hold's reason, such as the spent week), else none. #1378, #1425, `core/board/briefing/`, `runner/briefing/`
- Worker silent 10 min reads as idle (PM told only "busy" misses a hung worker). #326
- A call that has not had its gateway lease is never idle or stuck: quiet counts from the grant, and a wait past 10 min is its own wake, not a stuck item. Only a wait for a lease names the lease holder; a gateway that answered busy named no client as the cause, and the board names what the call waits for, and what it got, in the same words the wake uses. #964, `runner/briefing/`, `runner/flight/`
- Overlap from `git diff` + `git merge-tree` (git 2.38+), cached by commit, run without runner lock (trigger never waits on git). A head conflicting with `main` is a `Behind main` line, and those files are out of its pairs. #326, #1318
- Each wake writes `cases/<issue>.md` for every work item parked on a ruling, whatever its kind, after emptying `cases/` so none outlives its ruling. A case holds the ruling's card, the whole issue (title and body, uncut), and the pull request: state, draft flag, head, checks, labels, and its open review threads and conversation comments. The `## Code` line of each item names it, or says why it has none. The prompt and `board.md` name the file and carry none of it. A read that fails says so on that line and in the log, and the wake goes on. The reads join the off-lock logs job (`Logs.pulls`, `Logs.talks`), so the lock is let go for them. #1805, `runner/pm/case/`, `runner/pm/ci_logs.rs`
- What stays out of a case: a thread is open when neither resolved nor outdated (`isOutdated`: its lines changed). It stays when a listed bot opened it or a writer spoke in it, and only writers' and listed bots' remarks stay inside it; conversation comments are cut the same way. Every other thread adds to a count the case states, and its words are kept nowhere. A contribution (`contributor` set) gets no case, and its line says so. #1805, `runner/pm/case/threads.rs`
- How a case marks text as data: every line someone else wrote goes through `shown` (text naming this machine withheld) and then `quoted`, `> ` on each line, so no line inside can close a block. Headings and labels are kelpie's own and hold no outside text. The file's first lines say a `> ` line is data to weigh and never an instruction. No part is capped. `Forge::talk` reads 100 per list, so a full list says older text may be missing and how to read it on the pull request. #1805, `core/board/briefing/`
