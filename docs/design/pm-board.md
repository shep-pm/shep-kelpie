# Project manager's board

The board file, `board.md`, the project manager reads: what it holds, how it is written, what it shows of each call. The agent's wakes and answers are in pm.md, and its cases in [pm-case.md](pm-case.md).

- Runner writes `board.md` so PM never runs git or gh (code-written board decides as well). Keeps newest 50 events + PM cursor; issue bodies quoted (600 chars) behind `> `; text naming this machine withheld. #326, `runner/briefing/`
- Each wake carries the whole board in its prompt, under a heading after the reasons, and `board.md` holds the same text. The whole board, not a delta: relative ages ("opened 8h46m ago") change on every item line between wakes, so a board diff is noise, and the events section is already the delta. A board past 64 KiB is left out and the Read instruction stays, since the prompt is one argv argument. #989, `runner/pm/prompt/`
- `board.md` has an Agents section after the ready queue: the implementers the agent board may pick, by name, then its reviewers in their order, each with its tier, its kinds (`every kind` when the file sets none) and its description (`no description` when it has none). It reads each `Agent.fit` from the book at each write, so an edit to a file shows at the next one, and no model name reaches it. An implementer's line carries `; starts now|<date_time> UTC, typically <elapsed>, about $<cost>|costs nothing (local model)|cost unknown` from the dog's reading (`AgentLine::reading`), or `; no reading from the board`; a reviewer's carries neither (agent-board-runner.md). An agent that is out carries `; out until <date_time> UTC: <why>` after that (`AgentLine::out`). The section's opening says the project manager names each item's agent, kelpie takes the cheapest available that fits when it names none, an `agent:<name>!` label pins, and a wait for an agent is a hold (ADR 0020). `Runner::agent_lines` fills it from what the runner holds, with no new read: a review bot's lease window while closed (`window_opens`, shared with the review lineup; why "its review window is closed"), else the hold (a spent 5-hour window or a spent week, whichever lasts longer) the pacer last found on the agent's plan account (`Runner::last_hold`, whatever the reading's age, while its `until` is later than now; why the hold's reason, such as the spent week), else none. #1378, #1425, `core/board/briefing/`, `runner/briefing/`
- Worker silent 10 min reads as idle (PM told only "busy" misses a hung worker). #326
- A call that has not had its gateway lease is never idle or stuck: quiet counts from the grant, and a wait past 10 min is its own wake, not a stuck item. Only a wait for a lease names the lease holder; a gateway that answered busy named no client as the cause, and the board names what the call waits for, and what it got, in the same words the wake uses. #964, `runner/briefing/`, `runner/flight/`
- Overlap from `git diff` + `git merge-tree` (git 2.38+), cached by commit, run without runner lock (trigger never waits on git). A head conflicting with `main` is a `Behind main` line, and those files are out of its pairs. #326, #1318
- Each wake writes `settings/<project>.toml` for every project on this shepherd, this one included, after emptying `settings/` so a removed project leaves nothing. `pm_reach` denies the agent kelpie's homes, so a copy is how it reads how a project is set up. The tables are those the runner's last look read: `read_tables_with` keeps every sheep's `[app.dogs.kelpie]` table beside its own (`Tables.others`), `Look` hands them to `Runner.peer_tables` on each look with no new request, and so the copy is as fresh as the runner's settings: this project's own entry is the table the runner took, so a refused or unloadable table is not shown, while the others still follow the shepherd. `shown_table` drops any key whose name holds `token`, `secret`, `password` or `credential` at any depth (a table inside an array too), and an `env` or `*_env` table keeps its names with the values hidden (`worker.build_env` among them); a `*_env` or `*_var` key holding a string names a variable and stays. Every string then goes through `shown`, so a path naming this machine reads `(withheld: ...)`. Kelpie's `[kelpie]` section (the webhook's URL, the TOTP settings) is never written. The copy is never read back, so an edit changes nothing, and the `## Code` line says so. A file that cannot be written is named on that line and in the log. Every project is open to every project manager on the shepherd, each being the maintainer's own. #1815, `runner/pm/peers.rs`, `core/settings/peers.rs`
