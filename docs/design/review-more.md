# One more read

What a pass reads of the project manager's plan, and how a finding above a nit asks for one more read. The pass it sits in is in review.md.

## One more read

- A pass on a project that names `agents.pm` reads the plan's `reads` (`need_of` in `review-pick.md`), and each reviewer's prompt carries the plan's `about`, what the project manager wants those reads for (`plan_note`; none with no plan or no `about`; a local command or a bot takes no prompt). A round that sent a finding above a nit (a Medium or High, not a `Low`) asks the project manager for one more read once the worker's fix turn ends (`after_fix`, in place of `after_round`), when every read the plan calls for is in, a candidate is left (`due`) and the pass is not `bots_only`. It decides after `after_round_in` has chosen `Phase::Ci` or `Phase::Review`, since a skipped bot can keep a finished pass in review. An ask leaves the item at `Phase::Review` and idles it: `choose_reviewer` gives `Begin::Idle` until the answer. `read` `more: true` raises the plan to one above the larger of `need_of` and the reads the pass has in, keeping `about`, for the rest of the item, so the next step picks a reviewer, and a later pass on a new head reads that many too; `more: false`, no `read` entry, a failed wake or a restart ends the pass as it did before. The ask lives in memory, so the state file is unchanged, and a read that sends a finding above a nit may ask again, bounded by the candidates left and the item's spend cap. A project with no `agents.pm` asks nothing. ADR 0020, #1764, `runner/review/one_more.rs`, `pm.md`
- A reader's prompt ends with the pull request's body between markers, as what the author and the project's CI wrote and proof of nothing (`body_note`; the last 4,000 bytes, none for a blank one; a failed read is a `gate_failed`; no setting turns it off). #1802, `runner/review/prompts.rs`, `runner/review/criteria.rs`
- A project that names `agents.pm` puts every open thread of its own work item, nits included, to the project manager before the merge (`passed` in `runner/gate/`, after the disputes are posted). `Runner::rules_threads` is true with an `agents.pm` and no `contributor`. The item stays in `Phase::Ci` and gives `Begin::Idle` with `Reason::ThreadsAsked` while the ask is out, `PmDown` while `pm_available` is false (checked before the talk is read, so no wake runs) and `PushBack` while only pushed-back threads remain. `follow-up` files the finding `ready-for-agent` through `file_follow_ups`, which leaves `item.follow_ups` as `None` before the merge so deferred findings are still filed at it, replies with the issue's number and resolves the thread; `close` replies with the reason and resolves it, filing nothing; `fix` sends every fixed thread as one worker turn (`threads_sent`, `ReviewStage::Fixing`); `push-back` replies and keeps the thread open until the maintainer writes in it, noted in memory by its last remark, so a restart asks once more. A reply the guard or a hook refuses is replaced as `answer_sent` replaces one. A refused filing retries through `gate_failed`. An answer that lands after the item left `Phase::Ci` at that head acts on nothing, and the threads are asked again. A talk that cannot be read holds the item with `Reason::TalkUnread` rather than going past the threads. The deferred findings `read_deferred` returns (nits and disputed findings left out) ride the same wake, each as a `RuledThread` with no forge id and `DEFERRED_BY` for its author: `follow-up` files it and takes every copy of it out of the worker's deferred file (`findings::drop_deferred`), so `follow_ups` finds nothing at the merge; `fix` sends it in the same worker turn as the threads, and it leaves the file only when that turn pushed and the worker answered `fixed` (`leave_fixed_deferred`), so one declined or unmentioned stays deferred and is asked again; `close` drops it with its reason in the journal and replies on nothing; `push-back` has no thread to reply on, so `rule_threads` drops it and the finding stays unruled. A finding the worker defers again after a `fix` is ruled at the next wake or at the merge. A head merged by hand, a project with no `agents.pm`, an adopted contribution and a `follow-up` ruling already pending keep `Wake::FollowUp` and `settle_follow_up` after the merge. A thread only someone outside the project wrote in holds nothing and reaches no model. A project with no `agents.pm` keeps its nits holding nothing. No round limit: the spend cap (`over-budget`) ends a fix loop. ADR 0020, #1824, #1825, `runner/gate/threads.rs`
