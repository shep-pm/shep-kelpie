# Agent board, the runner's side

What the runner does with the agent board's answer: dispatch, add, rework and handoff. The estimate and the dog's side are in `agent-board.md`. ADR 0018.

- The runner's side (`runner/add.rs`, `runner/dispatch/`, port `ports::AgentBoard`, `DoorBoard` on `lease.sock`): a new work item from a ticket asks with the issue's `kind:` label, the project manager's tier and slack, the pin (an `agent:<name>!` label's, the only pin) and every implementer file `agents.allow` holds, by name, that the worker's fence and the gateways can run (`Runner::board_agents`); the answer is kept to those. Each one left out (`Settings::refused_implementers`, the one predicate) is logged at each start and at a reread that newly leaves it out, and `doctor` gives it an unsure `implementer <name>` line (it passes `GatewayKeys::Unheld`, since the runner reads a gateway's key from its sheep's `env`: a key doctor's shell lacks is the gateway's own `key` line) and leaves it out of its `implementers` line. Dispatch takes the first ranked agent `pace_agent` lets start, since the runner's reading of usage has the last word over the dog's ranking; a usage read pending stops the walk. A plain `agent:` label chooses nothing. The project manager's `agent` is not a pin (ADR 0018, amended 2026-11-04): `Runner::ranked` asks for it alone first and opens the item on it, unpinned, when the board ranks it with a `wait` within the item's slack (`starts_within_slack`), with the ranking behind it (a pinned label's agent alone, else the ranking, the pick left out) for the pacer's walk to fall to when it holds the pick, logging `#<n>: the project manager picked <agent>, which the pacer holds, so <other> takes it`. Otherwise it notes `#<n>: the project manager picked <agent>, which cannot start within its slack, so the agent board picks` and asks as if none were named: a pinned label's agent alone, else the ranking. An item a pick pinned before this stays pinned; `WorkItem::pinned` means only the label. No answer starts nothing this poll and lists the issue `unpicked`; an empty ranking lists it `unpicked` naming kind, tier and pin; every ranked agent held lists it `paced`. Each waits for the next poll, with no fallback pick, and the next issue may start. `add` takes the first ranked, unpaced. Rework, adopted and contribution items walk the ranking as dispatch does (`Runner::board_ranked`, `paced_opening`), a pinned label or none, and open on the first the pacer lets start; a `rework <pr>` by hand takes the first, unpaced. A dog that cannot be reached ends the walk over rework and adopted pull requests for this poll, as it ends dispatch's: no state changes, nothing is reported and `BoardFailed` is not, the pass goes on to the issues, which list themselves `unpicked`, and the next poll asks again. No default implementer is left. The walk is `first_unpaced` (`runner/pace.rs`). The `FakeAgentBoard` ranks the ask's agents in order until a test sets one, or `ranks_finishing` sets each finish; the rig's puts `sonnet-high` first (`ranks_first`).
- The `reading` ask (`AgentBoard::reading`, `DoorBoard`, `FakeAgentBoard::readings`, counted apart from `asks`): `Runner::read_agents` asks it with the implementers `board_agents` names, at each board write, and keeps the answer in `BoardCache` for 30 seconds (`READING_KEPT`) while the same agents are asked, since a write happens on every change. The dog answers a `Pick` for each agent it has a window for, whatever its kinds; an agent it leaves out, or a dog out of reach (the answer is kept too), reads `no reading from the board` in `board.md`'s Agents section. A pick that names no agent notes `#<n>: the project manager named no agent, so the agent board picks` (`first_choice`); a ready issue with no pick, a rework and an adopted pull request open the same way, with no note. A pick wake stays at two or more startable issues (ADR 0020 adds no wake).
- The `fit` ask (`runner/agent_fit.rs`, asked from `runner/ledger.rs`'s `append_finished`): a `finished` line naming an agent and a kind asks the board whether that agent still fits it, and `Fits::No` raises the `agent-fit` ruling on that item's pull request (who-answers.md). A line with no agent or kind, an item with no pull request, and a board that cannot be reached raise nothing, and nothing is remembered between finished lines: the next one asks again. Kelpie writes no agent file from a finding, whichever way the ruling is answered. State version 93.
- Handoff (`runner/turn/handoff/`): before each due turn of an unpinned item (one the project manager picked an agent for included), the runner asks with its kind, tier, slack, no pin and `leave_out` the agents it left (`WorkItem::left`). Its own agent, ranked with a wait within the slack (its own, else `agents.slack`), keeps the turn however long it takes, the same test dispatch gives a named agent (`starts_within_slack`), so a slow free agent is never moved for being slow. Otherwise, with `agents.pm` set and `pm_pace` clear (`pm_available`), an own agent that is out leaves the turn waiting on its own session (ADR 0020): `hand_off` records the agent and its return on `Desk` (`agent_out`), returns `Begin::Idle` with the held-up reason `AgentOut`, and `stuck_now` reads the record as `StuckState::AgentOut`, so `still_due` queues a `Wake::Stuck` naming the item, its agent and its return. The project manager's `pick` entry for that item (`pm/act.rs`, `pick_waiting`) moves it through `move_item` to the agent it names and takes no slot of the wake's. It is dropped, saying why, when it names no agent, one `agents.allow` leaves out, one the board is never asked about (`board_agents`: the worker's fence or a gateway key rules it out), one in `WorkItem::left`, the agent that is out, or any agent while the maintainer has the item attached (`WorkItem::attached`). `none` in `unstick`, or an answer that names nothing for the item, leaves it waiting on `pm_left_alone`'s back-off (renewed at each later wake the answer leaves unnamed, since `pm_unpicked` renews an entry that was asked), and any other `unstick` action is dropped, saying to name an agent in `pick`. An own agent that can start again drops the record and `wake_holds` the wake, and the turn runs on its own session. A turn that goes on for any other reason (the board out of reach, an empty ranking, a held agent) drops the record too, so a late pick finds no waiting item. A usage read the project manager's pacer still needs is made first (`Begin::Reads`). With no `agents.pm`, or a project manager that is down, held by the maintainer's terminal or past its pace, the record goes and the first ranked agent `first_unpaced` lets start on the turn's scope takes the item: a new session on the same branch, `Turn::Due`, its first prompt carrying `WorkItem::handoff`, kelpie's note of the branch's commits past the base (the newest 20, none before a worktree exists), the old agent's last `summary` (or that none is kept) and the prompt it was due. The note lasts until that turn ends, so a session that dies unborn starts over with it, and a second handoff before the new agent runs keeps it. An own agent a trusted pacer hold still holds asks nothing (`turn_still_held`). An API refusal moves its item at once through `next_pick` (`runner/turn/refused/`), with no wait for the project manager: every API agent shares the key that failed. The step log's `handed-off` line names `from`, `to` and both finishes; the board event says `handed off from <a> to <b>`; no label is written. No answer, an empty ranking, every ranked agent held, or an agent outside the ask's agents (no file, or `agents.allow` leaves it out, which fails its turn as agent-allow.md says) keeps the turn on its agent. State version 92.
