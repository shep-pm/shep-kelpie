# Agent board, the runner's side

What the runner does with the agent board's answer: dispatch, add, rework and handoff. The estimate and the dog's side are in `agent-board.md`. ADR 0018.

- The runner's side (`runner/add.rs`, `runner/dispatch/`, port `ports::AgentBoard`, `DoorBoard` on `lease.sock`): a new work item from a ticket asks with the issue's `kind:` label, the project manager's tier and slack, the pin (the project manager's agent, else an `agent:<name>!` label's) and every implementer file `agents.allow` holds, by name, that the worker's fence and the gateways can run (`Runner::board_agents`); the answer is kept to those. Each one left out (`Settings::refused_implementers`, the one predicate) is logged at each start and at a reread that newly leaves it out, and `doctor` gives it an unsure `implementer <name>` line (it passes `GatewayKeys::Unheld`, since the runner reads a gateway's key from its sheep's `env`: a key doctor's shell lacks is the gateway's own `key` line) and leaves it out of its `implementers` line. Dispatch takes the first ranked agent `pace_agent` lets start, since the dog reads no day allowance; a usage read pending stops the walk. A plain `agent:` label chooses nothing. No answer starts nothing this poll and lists the issue `unpicked`; an empty ranking lists it `unpicked` naming kind, tier and pin; every ranked agent held lists it `paced`. Each waits for the next poll, with no fallback pick, and the next issue may start. `add` takes the first ranked, unpaced. Rework, adopted and contribution items walk the ranking as dispatch does (`Runner::board_ranked`, `paced_opening`), a pinned label or none, and open on the first the pacer lets start; a `rework <pr>` by hand takes the first, unpaced. A dog that cannot be reached ends the walk over rework and adopted pull requests for this poll, as it ends dispatch's: no state changes, nothing is reported and `BoardFailed` is not, the pass goes on to the issues, which list themselves `unpicked`, and the next poll asks again. No default implementer is left. The walk is `first_unpaced` (`runner/pace.rs`). The `FakeAgentBoard` ranks the ask's agents in order until a test sets one, or `ranks_finishing` sets each finish; the rig's puts `sonnet-high` first (`ranks_first`).
- Handoff (`runner/turn/handoff/`): before each due turn of an unpinned item, the runner asks with its kind, tier, slack, no pin and `leave_out` the agents it left (`WorkItem::left`). Its own agent ranked within the slack (its own, else `agents.slack`) of the soonest finish keeps the turn. Otherwise the first ranked agent `first_unpaced` lets start on the turn's scope takes it: a new session on the same branch, `Turn::Due`, its first prompt carrying `WorkItem::handoff`, kelpie's note of the branch's commits past the base (the newest 20, none before a worktree exists), the old agent's last `summary` (or that none is kept) and the prompt it was due. The note lasts until that turn ends, so a session that dies unborn starts over with it, and a second handoff before the new agent runs keeps it. An own agent a trusted pacer hold still holds asks nothing (`turn_still_held`). The slack rule is `within_slack`, which the dog's pick shares. The step log's `handed-off` line names `from`, `to` and both finishes; the board event says `handed off from <a> to <b>`; no label is written. No answer, an empty ranking, every ranked agent held, or an agent outside the ask's agents (no file, or `agents.allow` leaves it out, which fails its turn as agent-allow.md says) keeps the turn on its agent. State version 92.
