# The maintainer's issue, rewritten

The rewrite and the ready path of a pass. The pass itself: `triage-pass.md`; the check that reads the rewrite: `triage-check.md`.

- `body` is in the issue skill's format: the call loads `kelpie-issue` (`Skills::issue_plugin`), which `agents/triager.md` names rather than repeat. A question with a good answer is `Assumed: <answer>. Say otherwise.` in it, `open` the rest. The reply's `kind`, one of `check::kinds`, goes on as `kind:<type>`, made if missing, unless a `kind:` label is on. `runner/triage/{research,rewrite}.rs`
- A first pass over the maintainer's or the App's issue whose `body` the check refuses (`rewrite::refusals`, the body's parts only, not the labels) gets one repair in the same session: the check's reasons and the shape it reads, and nothing researched again (`redraft_prompt`). The repair's reply replaces the first if it reads, a repair that fails or does not read leaves the first draft, and a runner stopping during it asks the pass again at the next poll. The answers pass and the local read are not repaired. #1610. `runner/flight/triage.rs`, `runner/triage/rewrite.rs`
- With no open question and a `body`, `readiness` rewrites the maintainer's issue (`Runner::own_author`: the maintainer or the App). If the check passes the listed title, the body and the labels the pass began with as its own change them (`passes_with`), the body goes over the issue's on the ready path below. If not, it goes under the issue's text as settled answers do (`settled_answers`, `answers`, `commented`, the labels, `needs-triage`), never over it, and the re-check says what was refused. An outside issue is never made ready. `runner/triage/ready.rs`
- The comment says ready, with the priority, or, for a rewrite, that the check still refuses it. It is promised only where kelpie can keep it: no hand triage label stands, and the local guard passes the body. `facts.rs`
- `Voice::edit_issue_body` replaces the body, the title untouched: `AppVoice` sends `PATCH /repos/{owner}/{repo}/issues/{number}` naming only `body`, through `GuardedVoice`, `PacedVoice`, `RecordedVoice`. A body naming a path on this machine is dropped before the wording (`LocalPaths`), and the issue ends at `needs-triage` as written. A `publish` hook's refusal is said on the issue in a short notice. `ports/voice.rs`, `github/voice/`
- On the ready path the comment is followed by the body edit (`body-written`), the labels, the removal of an earlier pass's `needs-triage`, and `ready-for-agent` last (`ready`), made if missing. The `labelled` step is not used there.
- A refused edit is told once and tried at the next poll. Once `body-written` is saved the body is never written again: `ready_body` holds it at `commented`.
- A triage label put on by hand stands. The labels the issue began its pass with (the record's `seen`, kept over a restart) are read against the issue before the wording, the body write, the labelling and `needs-triage`, so one that came by ends the pass at `done`, body kept, nothing more labelled. At the labelling step `ready-for-agent` is kelpie's own, and the step finishes. `ready.rs`
- `ready` counts as finished: pruned like `done`, no new pass. The board takes it as any `ready-for-agent` issue, its `agent:` label as ever.
- A `ready-for-agent` the maintainer took off stays off. `IssueCheck::ready_seen` is true once the issue has carried the label: set from any listing that carries it, before the same-key skip and with no forge call, and by `check_passed` and `label_ready` when kelpie puts it on. The maintainer's passing issue with `ready_seen` and no label gets none and one note, and `readiness` returns `Not` for it, so a pass ends at `needs-triage`. `swap_ready` clears it before the label comes off, since the take-back is kelpie's. A label put back by hand stands and is seen again. A closed issue's result stays while it holds `ready_seen`, the newest 200, so a reopened issue is not made ready again. An older file seeds it from `passed()`, so a decided label with no `READY` stays off, the safe direction. State version 102. A key or `check::VERSION` change alone cannot be the rule: a failing edit then a passing one reruns the check. `runner/triage/{checks,ready,hand}.rs`
- The triager judges size itself and answers `split`, a list of `{title, body, priority, kind, after, agent}` (`research::Drafted`), with the project's implementers in the prompt (`implementer_files`). `readiness` turns it into `Ready::Split` and saves it as the plan in `record_triage`, one commit with the record. Only `own_author`'s issue keeps it: from anyone else it is dropped (#1847). The parent's `body` is checked like a draft, and a draft's `agent` becomes `agent:<name>!` through `agent_label`, an unknown name refusing the split. A named family is one picked agent and an `Assumed:` line. A draft or parent that fails the check or names a path on this machine (`self.local.find`) gives `Ready::SplitRefused`: nothing is filed and the comment says why. A draft with no priority takes the one the issue carries, else the triager's. The parent gets the pass's kind and priority labels before its drafts are filed. A pass that ends with no body written (a refused or moved body, a hand label) takes back a plan with nothing filed (`unplan`). No redraft. `runner/triage/{research,ready,split,facts}.rs`
- A saved split (`TriageState::splits`, a `TriageSplit` per parent: `drafts`, `filed`, `asked`) is filed in place of `ready-for-agent` where `label_ready` finds one, so `body-written` stays the retry point and no step is added. `split_refusals` runs the issue check over every draft first, and a failing draft files none: `notice_on` names the draft and why, the record ends `done`, and the parent stays with its entry. `asked` set holds the filing with no failure counted. A parent never gets `ready-for-agent`: `check_passed` leaves it, and the labels it carries come off before the first draft goes. State version 103. `runner/triage/split.rs`
- Someone else's issue never files on its own word: only the maintainer's yes starts git work, and the gate is code. `readiness` saves the plan as `Ready::Ask` with `asked` set to the triage comment, and no body is written. `finish_triage` posts a new comment naming `maintainer()` once the pass ends, and `asked` holds that comment. `triage_waits` includes it, so `thread_job` reads the thread and `hear_triage` hears it from the maintainer's login alone (`their_replies` takes the issue and the login). `says_yes` reads a reply that is only `yes` or `ok` and clears `asked` and steps the record to `body-written`; `no` drops the plan, other text leaves the wait open, and silence `triage.wait_days` drops it with no App needed. `label_split` holds while `asked` is set. `runner/triage/split_ask.rs`
- Per draft, in order: its labels made (once an attempt), `file_ticket` with `Slice <n> of #<parent>.`, one `Blocked by:` line (the `after` drafts and the body's own) and a last line `<!-- kelpie:split <parent> <index> -->`, `filed` saved, `add_sub_issue`, `add_blocked_by`, then `ready-for-agent` last. One `open_issues` read an attempt finds a body filed before a lost answer by its marker, so a retry files nothing twice. A restart relinks the last filed draft, since the links and labels are idempotent. A busy forge retries at the next poll, a hand triage label ends the filing, and `triage_busy` leaves a child alone until its parent's record ends. An entry goes when its issue leaves the listing (`settle_splits`). A start or reread that turns triage off, as a local ticket source needs, notes each split left part filed (`split::stopped`). `runner/triage/{split,checks,poll_read}.rs`
