# CLI adapter

One adapter runs every CLI. A CLI's own part is a file of what is true of it. The agents area is in agents.md.

- `CliAdapter<C: Cli>` implements `Agents` once: refuses a call routed to another harness, checks a session is new or resumed, empties the scratch folder, wraps the command in the sandbox, spawns it labelled, maps `RunError` to `AgentError`, and adopts a call across a handover. For a CLI whose facts say `needs_model_server` it also opens the forwarder, takes the gateway lease on a worker's chat calls and notes both for a handover. For one whose facts say `SessionIds::Cli` it keeps which of its ids each CLI session is. `crates/adapters/src/adapters/cli/`
- `Cli` has `const HARNESS` and `type Begun` (what a call learns before it spawns), then the hooks. Required: `write_config` (wires `kelpie guard` and `kelpie confine`), `command`, `policy`, `parse` and `parse_adopted`. Defaulted: `refuse`, `answer`, `begin`, `ready`, `scratch`, `sandbox_settings`, `folders`, `follow_up` (a second command after the call, as goose's `session list`), `adopted_begin`, `started`, `ended`, `transcript`, `last_active`, `mcp_refusal`, `mcp_skipped_env`. A default that does nothing is a tracked gap in `docs/parity.toml`.
- One `HarnessFacts` row per harness (`crates/core/src/settings/agents/facts.rs`) holds what callers read instead of matching: name, program, usage reader, model server, `tools`, `guard_hooks`, `after_command`, who picks session ids, writing tool, `.claude` files, ends at a tool, browser, kept servers, empty folder, transcript format, whether the runner counts its calls, whether it runs the PM, why a handover waits while a session is attached, the role `status` gives that session (`attached_role`) and which probe `doctor` runs (`doctor_probe`). `Harness::` is matched there, in the serde names, in `AgentHarness::on`, in the conversions and in the routing list, and nowhere else outside each CLI's `const HARNESS`.
- Output is always files, so it is no fact. Shared helpers (`Base`, `fence_policy`, `Records`, step skills, `tail`) are in `crates/adapters/src/adapters/harness/`, and no adapter imports another's module.
- A fifth CLI is one folder `adapters/<cli>/` with an `impl Cli`, a row in `facts.rs` (and `Harness::ALL`, `AgentHarness::on`), an entry in `McpRules` if it refuses or drops a server, and one `(Harness, Arc<dyn Agents>)` entry in `Routed::new` in `src/sheep/mod.rs`. No other match on `Harness` or `AgentHarness` needs an edit.
- A test builds a CLI on the same trait: `ScriptCli` (`crates/runner/src/test/script_cli.rs`) is one shell line run through the rig's stand-ins. `Routed` sends a `StandIn` call to the Claude Code entry, so a rig that lists none still runs.
- A call routed to a CLI that its `Cli::HARNESS` does not name is a `Setup` error. `Routed` panics only on a harness no entry names.
- A call on a model behind a paddock gateway puts what its lease used on `AgentReply.metered` (`Metered`: watt-hours, a cost where the host is priced, and `wall` or `parts` as the source), read off the release's `Paddock-Energy-Wh`, `-Usd` and `-Source` headers. An adopted call reads it from its resumed lease. A header missing or unreadable gives `None`, as do an `openai` gateway, Codex and a local review round (#1650).
