# Browser

A worker looks at the UI it builds through a browser kelpie runs outside its sandbox. ADR 0011, #858, #859, #860, #861.

## Always

- `[app.dogs.kelpie.browser]` (`enabled` off, `headed` off, `domains` empty, `configuration` unset) in `crates/core/src/settings/browser.rs`. `domains` takes the form of `worker.allowed_domains`: a host, or `*.` and a parent. A port, an IP address and `localhost` are refused, since Chromium's resolver rules name hosts and cannot hold one to a port.
- Only a worker's `Work` turn gets it, with a non-empty prompt that is not `COMPACT`, on a project with the table on, on macOS, on a harness whose `drives_a_browser` is true (Claude Code, pi, Codex and goose), on a GitHub or a local ticket alike: a call names its work item by `TicketId`, so a `k12` turn gets the browser as a numbered one does (`may_browse`, `ticket_of`). Reviewers, the project manager and `attach` get none. `runner/browser.rs`, parity row `harness.browser`
- On Linux an enabled table stops the runner at start with `Exit::Refused`, naming #135. `src/sheep/mod.rs`
- `Runner::prepared` opens a bridge through the `Bridges` port (`crates/core/src/ports/bridge.rs`; the real one is `Bridge` in `crates/adapters/src/adapters/bridge/mod.rs`) and names its socket in `Reach.browser`. The turn's flight holds the handle, and dropping it closes the bridge. The tools missing is a note and a run without. A bridge that cannot open fails the call, since the instructions promise a browser.
- The socket has a 128-bit random name in the worker folder, checked with `home::socket_fits`. The name is drawn once per work item and kept in `<project>/browser/<issue>/socket-name`, so every turn's bridge binds the same path: a goose session keeps the `playwright` command it began with, and a resumed call adds no flag. kelpie notes the id of the session it opened the browser for in `<project>/browser/<issue>/session`. A session that began without a browser stays without one: a resumed goose call whose session is not the noted one gets no browser and its instructions do not name one. Parity row `harness.resumed-servers`. The sandbox may connect to that path only (`fence_the_browser` in `crates/adapters/src/adapters/mcp/mod.rs`, called by Claude Code, pi, Codex and goose).
- The agent loads it as the MCP server `playwright` (Codex through a `-c mcp_servers.playwright` override, goose through `--with-extension` on a new session), running `kelpie mcp-connect <socket>` (`crates/core/src/bridge.rs`), which carries stdio to the socket.
- A fresh Playwright MCP server per connection, in its own process tree, outside the sandbox: `node <tools>/node_modules/@playwright/mcp/cli.js --config <file> --isolated --output-dir <dir>`, plus `--headless` unless `headed`. `PLAYWRIGHT_BROWSERS_PATH` is `<tools>/browsers`. Dropping the bridge shuts the connection, stops the server's tree (TERM, then KILL) and removes the socket.
- The config and output folder are `<project>/browser/<issue>`, made by kelpie and refused if they are a link. The worker cannot write them: the server resolves a file's symlinks, so a folder the worker could write would write anywhere.
- Chromium launches with `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE <domain>...`, so every other host, every IP address and every WebSocket to an unlisted host fails to resolve.
- Every line is judged both ways (`Filter` in `crates/core/src/bridge.rs`). Inbound passes `initialize`, `ping`, `tools/list`, notifications, replies, and a `tools/call` on a tool in `TOOLS` whose arguments `browse::judge` allows. Anything else gets a JSON-RPC error with the request's id. Outbound, a `tools/list` reply is cut to `TOOLS` and a line that is not a JSON object is dropped.
- A `tools/call` unanswered for `CALL_LIMIT` (90 s, past Playwright's own 60 s navigation timeout; a `browser_wait_for` gets its `arguments.time` on top) is ended by `serve`. The worker gets an `isError` result for it and for every other call waiting, and one stderr line names the tool and the limit, never its arguments. The server is stopped and a fresh one started on the same connection, with the `initialize` and `notifications/initialized` replayed (its reply is swallowed). The page's state is gone. A reply for an id not waiting is dropped.
- `TOOLS` is an allow-list of 19. A tool a Playwright upgrade adds is refused until listed. Left out: `browser_run_code_unsafe`, `browser_file_upload`, `browser_drop`, `browser_set_storage_state`, `browser_install`.
- `browse::judge` (`crates/core/src/browse.rs`): a `url` passes only as `http` or `https` to a listed host. Any `filename` is refused, so a screenshot comes back in the tool's reply. `localhost` and `127.0.0.1` pass only on the dev server's port (`Filter.dev_port`).
- `@playwright/mcp` is pinned exactly in `crates/process/src/tools/package.json`. `tools install` also fetches Chromium into `<tools>/browsers`, and names each tool, its pinned version and its result as it goes (`crates/process/src/tools/install.rs`, #884). `doctor` says when a project has the browser on and the tools lack it. On Linux it also checks installed headless shells with `ldd`, naming missing libraries and Playwright's `install-deps` fix. A failed probe is `unsure`. `crates/process/src/tools/browser.rs`, `src/doctor/project.rs`
- The worker's instructions name the `browser_*` tools, the hosts, and say to wait in the foreground, since a turn that ends on a background task is never woken under `-p`. `runner/instructions.rs`
- The bridge belongs to the turn's flight and ends with it. `carry_calls` refuses a handover while a worker turn holds one, naming the issue. `runner/flight/carry/`
