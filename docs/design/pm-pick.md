# Project manager picks

What the project manager's `pick` and `hold` say and how kelpie reads them. The agent is in pm.md.

- A `pick` of null is no preference: the board rule fills the free slot at once, with a work item open or not. The board waits on a pick wake only while its call runs, which ends at its answer, its failure or the 10 min call ceiling; a wake queued behind another PM call waits for that call too. A null pick covers the free slots for the issues its wake offered, with one call; an issue that turns ready later wakes it again. A hold is `{ issue, until }`, `until` an open work item (else refused with a note): it ends when that item closes or the issue's title or body changes, so the PM need not hold again each wake; an answer with no `hold` keeps them, `[]` clears. A bare issue number has no `until` and ends at any close. Holds are saved, so a restart starts none of them. #327, #1321, `core/state/pm_holds.rs`
- `pick` is one ticket or a list in the order to start, up to the free slots the wake told (extras are dropped and named). Dispatch opens one item a step, taking the next of the list through the usual overlap and hold checks, so a wake fills every free slot. An entry keeps its place until its work item opens; an entry the board cannot take is dropped like a single pick and the next goes. #1223
- A `pick` entry may be an object `{ issue, tier, agent, slack, light, review }`, every key but `issue` optional (`tier` light, standard or heavy; `slack` whole minutes, 0 allowed; `light` a boolean, absent or null for false; `review` an object of `reads`, a whole number of at least 1 with no ceiling, and `about`, optional text on what the reads are for, cut at 300 characters, blank reading as none); another key or a malformed value drops the entry, named. An `agent` that is no implementer file `agents.allow` holds drops the pick; one that is is tried first, unpinned, over the issue's own label, which is left as it is, and runs the item only when the board ranks it able to start within the slack (agent-board-runner.md). Tier and slack are kept on the work item (state version 91) and go in the agent board's ask (agent-board.md). `light` is kept as `pm_light` (state version 97), a tag kelpie reads for nothing: the weighing lightens no review for it, and the next slice takes the key out. `review` is kept as `review_plan` (state version 100, ADR 0020), and a pass runs its reads (`review-pick.md`). A pick no agent can start is dropped saying why, and that issue wakes no pick until it starts, so an unstartable pair cannot wake it every poll. `runner/pm/picked.rs`, ADR 0018
- A pick of an issue stands whatever opens or closes. Dispatch drops it only where the issue is no longer one the board can take, which logs a `pick-dropped` step with why and tells the PM at its next wake. #1222
