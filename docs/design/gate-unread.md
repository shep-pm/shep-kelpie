# The head no reviewer read

What the gate does with a head only a review read can clear, and the wait when no reviewer can read it. CI and the merge are in [merge.md](merge.md), the pass in [review.md](review.md), rulings in [rulings.md](rulings.md), and the project manager's wakes in [pm.md](pm.md).

- The merge trusts only a head a round read, or one kelpie sent to CI unread on purpose: a fix turn's push, its own catch-up with `main` of such a head, a pass no candidate could read, or an adopted pull request's head as it arrived. Any other head, such as one pushed by hand, is unread. #290, `core/work_item/known.rs`
- Only a review read clears an unread head, so a ruling on one decides nothing. On a project whose project manager rules on its items' open threads (`rules_threads`: `agents.pm` named, and the item is no contribution), the gate sends such a head back through a pass of the review before anything else the gate reads, and raises no merge ruling: an unreviewed pass, a head no round read (`unread_head`), the fix a merge ruling's `no` or a person's comment sent (`note_fix`), and the fix for a bot's late round (`late_fix`). A head kelpie sent to CI unread on purpose is vouched for and merges. `runner/gate/unread.rs`, `runner/gate/mod.rs` (#1826)
- The pass back runs what the item's review plan gives, `need_of` where its pick planned none, and raises no plan of its own. `runner/review/lineup/weight.rs` (#1826)
- A pass that ended short of its reads because no reviewer could read (every candidate down, passed over, or out of its window) waits at the gate instead of going straight back: a new pass would read nothing and cost nothing, so the loop would end only when a reviewer came back. No round runs, no ruling raises, `status` and the board name the wait (`held_up`, `Reason::ReviewerDown`), and one new pass starts every `READ_AGAIN` (30 minutes, no setting, as long as the project manager's first wait on an idle call) until a reviewer reads the head. `runner/turn/held_up.rs` (#1826)
- The first `READ_AGAIN` that ends with no read wakes the project manager once, with a `stuck` wake (`StuckState::ReviewerDown`) naming when the head was last read and that kelpie starts a new pass every 30 minutes; later waits wake nothing, and a wake that answers nothing changes nothing. The wait is in memory (`Desk.read_again`), one per open ticket, cleared when a read lands or the item ends, so a restart starts it over. `runner/pm/wakes.rs` (#1826)
- Going back from a reviewer-down wait clears `local_failures`, so a local reviewer that failed twice for the item is tried again in the new pass. `core/work_item/local.rs` (#1826)
- A pass the project's own list left short (`paths`, a bot's `rounds`) marks nothing and merges. A project with no `agents.pm`, and an adopted contribution, keep the warned merge ruling, whose question says it reaches the maintainer only for that reason. `runner/ruling/question.rs` (#1826)
- Under `merge = true` the merge ruling a project with a project manager still raises is raised by another open pull request closing the same issue (`rivals`), a head carrying another pull request's commits (merge.md), or a comment the guard or a hook refused (review.md). Open review bot threads hold the item in CI for the project manager's own ruling instead (review-more.md). #1826
