# Workers

Runner loop, worker turns, agents, harnesses. The fence is in fence.md, skills in skills.md, plugins in plugins.md.

## Runner and turns

- Loop never waits on an agent call: each runs on its own thread, one per item, beside the PM's (triggers and `status` answer meanwhile). #318, ADR 0005, `runner/flight/`
- `status`, `drain`, `undrain`, `timings`, `board` and, queued, `add`, `rework`, `adopt`, `triage` and `rule` answer from a copy the loop posts, not from the runner's lock, which a pass holds a step at a time, less the reads it hands to jobs. A `drain` or `undrain` answered that way sets its flag at once and leaves the rest for the pass. One answered with the lock free takes up what the other left waiting, so the last ask stands either way, and a `drain pause` asked for once is asked for. A pass checks drain again after it prepared a turn (token mint and worktree ask the forge with the lock held), and a step made again after its read. A review round checks again after it reads the issue whose criteria it reviews. No forge read sits between a step's check and the call it starts: `main`'s workflows are read before any item is stepped, not after the pass chose its call. The loop posts again when a call goes in flight, so `drain` never says nothing runs while one has. #916, `runner/posted.rs`
- A project's base branch is a value, `Git::base()` in `crates/core/src/settings/git.rs` (`git.base`, `main` when absent), not a constant. A work item records it when opened, so a change reaches only later items; their worktree, pull request, turns, review and merge read the record, the rest the setting. The guard is its own process, so it gets `--base=<branch>`, emitted only when not the default. #1047
- Harness files carry the issue (`settings-<issue>.json`); runner git waits 2s for a ref lock, 5s for `packed-refs`. `runner/turn/`
- On stop: ask each call's process tree to end (SIGTERM to its process group; on Windows the job object is terminated), save, exit inside shep's 1.6s `kill_timeout`; restart resumes each item from its session. A `handover` trigger instead keeps the calls running (agents.md). ADR 0005
- A process tree is stopped through `crates/tree` (`Tree`, `Lead`), never `kill`, `ps`, `pkill` or `pgrep`: a process group by syscall on Unix, a job object on Windows that the child joins as it starts, so a process it starts first escapes. Interrupts come through `interrupt::Interrupts` (Ctrl+C and Ctrl+Break on Windows), exit codes through `status::shell_number`. Handover stays Unix-only. #1148, #241
- Worker owns one item, builds inline, no plan or crew; instructions and headless rules forbid sub-agents. ADR 0006
- Compaction is in compaction.md: `WORKER_COMPACT_PAST` (150k), `worker.compact_window` and the `COMPACT` call, on each harness. #760, #761, #770, #792
- Agents never see budget numbers (it makes models stop after each task). `runner/turn/budget.rs`
- Implementers default `sonnet-high`, `opus-high` for work hard to undo. #313
- `worker.turn_timeout` (60 min) counts from turn start, so restart buys no hour; past it parks `turn-timeout`, unless the worktree shows a commit the base lacks or a file written in the last 10 min: then the turn resumes with no ruling, up to 3 times per work item (`ceiling_resumes`; #1040); lease wait refunded. #16, `runner/turn/unfinished.rs`
- Failed turn parks `stuck` `turn-failed`. #57
- First prompt: title, body, the maintainer's issue comments (16 KiB). #996
- Pause ends a Claude Code or pi worker turn at its next tool result, not its end: runner writes `kelpie-pause` in the item's build folder (the one folder the guard can read); `kelpie guard --pause=<build>` as `PostToolUse` answers `{"continue":false}`, pi's guard extension calls `ctx.abort()`, each leaving `kelpie-paused` to mark the turn. No unpushed check, review or ruling, same stage, no slot or lease; next start resumes with a fresh ceiling, 10 min after `undrain keep` (work.md); a Codex or goose call keeps the old pause. #821, `crates/core/src/guard/pause.rs`, `runner/turn/paused.rs`; log lines: log-lines.md
- `[builds]` `max_gb` (20) caps an item's build folder, `min_free_gb` (20) keeps disk free (0 = off). Folder and disk are read once a minute per item during a turn; past a limit the runner pauses and logs once. After the turn it prunes the cargo cache it did not touch (`incremental/`, `deps/`), then resumes with the pause prompt, or holds (`held_up`) while over. `status`: `build_bytes`, `disk_free_bytes`. #857, `runner/builds.rs`
- First turn ending with no PR or question resumed once, then parks; uncommitted work with no push sent back once to commit; a yes on a turn-ceiling ruling resumes with the same ask (`TIMEOUT_CONTINUE`: commit any work that builds, then carry on). #140, #275, #1036
- Item whose issue closed with no work ends with no ruling; a parked item's issue is read every 5 min, a failed read again at the next pass. #385, #1205
- Worker asks with a `<kelpie-question>` block ending its message; parks on a `question` ruling with optional `- ` choices. #13
- Instructions tell a worker with commits made to push and have its draft open before it ends on a question (`OPEN_YOURSELF`, `HAND_OVER`), so the ruling is posted on the pull request: turn-end discovery runs for a question turn too, opening a hand-over worker's draft from its file, and the saved resume is `ReviewFirst`. With nothing pushed it is posted on the issue, or kept on a local ticket. #1037, `crates/core/src/profile/mod.rs`, `runner/turn/ended.rs`
- A choice only the maintainer can carry out (run a command, change a setting, grant a permission) starts with `You`, names what they do and what the worker does after, in the worker's instructions and the PM's `candidates` and `escalate`: an answer is the worker's next turn, so a bare verb reads as an order to a worker that may be unable to obey (shep#829). Neither prompt offers more worker GitHub access as a choice; the token's scope is a design decision (`docs/design/github-app.md`). #805, `crates/core/src/worker-instructions.md`, `runner/pm/prompt.rs`
- A worker whose item depends on an external API it cannot read the docs of asks in a `<kelpie-question>` block before it guesses, offering the issue's docs pasted in or the host in `worker.allowed_domains`. `tools` on a Claude Code agent file adds `WebFetch`, bounded by those domains. #997, `crates/core/src/worker-instructions.md`
- `shep kelpie attach <issue>` hands a worker's Claude Code, pi, Codex or goose session to maintainer, sandboxed (goose: `goose session --resume --name <id>`, `GOOSE_MODE=approve`, so it asks before each tool call and the hook still refuses what a worker may not do); held by pid + start time. #325, #766, #775, #796
- PR template filled, ending `Resolves #<issue>`; no repo template means the owner's `.github` one, read at start and reread, cut past 8 KiB, and written to `pull-request-template.md` in the item's build folder on every worker call, which the worker reads when it writes its body: the instructions only name that file, since Claude Code carries them on every request and the template is used once (#992). `worker.instructions_file` adds project rules. #596; #87, `runner/instructions.rs`
- Out-of-scope finds named in final message; deferred review findings in the deferred findings file, each with its reason on the next line, indented by two spaces, kept on the journal's `deferred` outcome (#1087), whose path, with the disputed findings rules and the design-choice rule, is in the header of the findings file a fix turn reads rather than in the instructions (#992); PR stays on its issue. #649, `runner/follow_up/`

## Not built

- Claude Code through a gateway: needs per-harness forwarding + a pacing decision. Gateways go through a port (`crates/core/src/ports/gateway.rs`) with paddock and `openai` adapters; `openai` holds no lease and may evict a turn's model. #352
- Usage calculator handing workers decisions, never cost figures. `docs/design-log.md` Decided, not built
- Shots on the pull request: in git history. ADR 0006, #54, #131. The preview's other half, a live look at the UI, is built as the browser (browser.md). ADR 0011
