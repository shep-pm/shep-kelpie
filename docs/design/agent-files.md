# Agent files

The agent file and how a file builds on one. Harnesses, gateways and the agent settings are in agents.md; the shipped agents and baselines are in agent-baselines.md.

- Agent = `<name>.md`, YAML frontmatter tagged `role` + Markdown body; a file that cannot be read stops the runner. One that cannot be used is left out and logged, file + line, so it stops only what names it: a setting (refused, old settings stay on a reread), or an open work item's agent (a reread refused, a start stopped). A left-out name never falls back to the shipped agent. serde-saphyr (serde_yaml archived). ADR 0006, #313
- `needs` optionally replaces the role's default needs, including `[]`: `implementer` needs `[edits, resumable-session]`; `reviewer` and `triager` need `[repo-reads]`; `pm` needs `[role-guard]`; `representative` needs none. The PM always requires `role-guard`, even with an empty or smaller override. It means kelpie's PM guard is wired by the adapter. Names are kebab-case, unknown names are refused with their line. It merges through `extends` as a whole key, so a child replaces the parent's list. The loader checks session harnesses against those needs before constructing the agent; command, endpoint and bot reviewers keep their own contracts. #1285, `crates/core/src/agents/needs.rs`, `front/mod.rs`
- `description`, `kinds` and `tier` are the keys the project manager and the later board choose an agent by, on `implementer` and `reviewer` files only (any other role refuses one as an unknown field). All three are optional and stay absent on `Agent.fit` (`Fit`), so a listing can say "no description". `description` is free text, not blank, no length cap. `kinds` is a non-empty list of lowercase words (letters, digits, `-`) with no repeat; absent takes every kind. `tier` is `light`, `standard` or `heavy` (`Tier`, ordered); absent reads `standard` (`Fit::tier()`). A bad value is refused with its line. They merge through `extends` as whole keys, so a child that sets one replaces its parent's value and one that sets none inherits it. There is no `limits` key (the `$` per day and hours of ADR 0018 dropped: the meters' windows are the only limits an agent has), so a file setting it is refused as an unknown field. The shipped agents carry them: each whole file sets `description` and `tier` (`coderabbit` `cubic` `codex` standard) and each baseline a reviewer can list (`defect-hunter` `standards` `spec`) sets `description` only, since it names no model and the operator's file adds a tier with the binding; no file sets `kinds`, so each takes every kind, and `pm` `representative` `triager` `security-reviewer` stay without the keys. A shipped description is one sentence on the work it fits, with no cost word or budget figure. Nothing picks by the keys yet: `agents list`, the `doctor` implementers line (unsure for a listed implementer with no description) and the board's Agents section show them. #1378, #1422, #1424, #1425, `crates/core/src/agents/fit.rs`, `front/mod.rs`
- `login` names the credential a Claude Code call carries: `plan` (absent reads `plan`) is the Claude login, `api` is the API key, whose credits the maintainer prepaid. `implementer` and `reviewer` files take it on a session; a reviewer on `command`, `endpoint` or `bot` refuses it as it refuses `usage`, and any other role refuses it as an unknown field. A harness with no API login yet (pi until #1660, Codex, goose) refuses `login: api` naming the harness, with its line (`harness.api-login` in `docs/parity.toml`). `login: api` is `AgentHarness::ClaudeApi`, so no call builder changes. The key's one path to `claude`: the runner's `env` holds `ANTHROPIC_API_KEY`, `ApiKey::take()` reads it once and hides it from every other process, and `program_command` sets it on a `ClaudeApi` call alone, with no `CLAUDE_CODE_OAUTH_TOKEN`; a plan call never sees it. A `ClaudeApi` call with no key refuses with the fix. The agent is still paced on the plan's windows (`limit()` is unchanged), which only over-paces. `doctor` reads the key from the runner's `env` only and asks for the Claude login only when some Claude Code agent is a plan agent. `crates/core/src/agents/front/mod.rs`, `crates/adapters/src/adapters/claude/sandbox.rs`
- Reread each wake (edits land live). Item keeps its agent, runs the file as it is now. #313
- `extends` merges frontmatter keys as text before parsing (every check applies); parameters on a reference refused (each a new label + ledger key). #386, `crates/core/src/agents/extends.rs`
- `body: append` in a file's frontmatter puts its body after the parent's, blank line between, at each step of a chain. No `body` key: a non-empty body replaces the parent's, an empty one takes it. Any other value, or the key twice, refused with its line; blanked in the merged text so later lines keep their number. #1190, `crates/core/src/agents/extends.rs`
