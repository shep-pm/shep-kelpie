# Local tickets

A project on `tickets.source = "local"` takes its tickets from files in kelpie's home, not GitHub issues (ADR 0014). The default, `github`, is unchanged.

- `[tickets] source` (`crates/core/src/settings/tickets.rs`). `Runner::open` puts a `Routed` port (`crates/core/src/local_tickets/routed/mod.rs`) over the held GitHub port and `LocalTickets` over `ProjectPaths::tickets()`, `<kelpie home>/<project>/tickets/`. `Guarded` still checks writes. A reread sets the source the board reads through a `SharedSource` (`crates/core/src/local_tickets/routed/source.rs`) the runner and `Routed` hold, and the log says `tickets now in effect`. #1011, #1121
- A call about one ticket goes to the source its id names, so a work item opened before a change of source keeps working. The board's reads (`ready_issues`, `finished_parents`) go to the project's source. `create_issue` and `open_issues` stay on GitHub, since `open_issue` (contributions) files a GitHub issue and needs its number. What files for the project itself goes through `file_ticket`, `open_tickets` and `comment_ticket` (`crates/core/src/ports/tickets.rs`), which default to those two calls and which `Routed` sends to the board's source. Only GitHub calls are held and ledgered.
- A ticket is `k<n>.md`: YAML front matter (title, labels, state, parent, blocked-by), the text, then comments, each after a `<!-- comment: <author> <unix> -->` line. A text holding such a line is refused. `crates/core/src/local_tickets/mod.rs`, `crates/core/src/local_tickets/file.rs`
- The next id is the highest on disk plus one, taken with an atomic hard link, so two `ticket new` calls never share one. A change to a ticket (`LocalTickets::update`) holds `k<n>.md.lock` while it reads and writes back, so the runner and `ticket edit` never lose each other's change. A lock older than 30 seconds is taken for a dead process's, and broken by one caller at a time, under `k<n>.md.lock.break`, which looks at its age again first. Scratch `.new-*` and `.md.tmp` files are ignored. A link to a ticket the store lacks is refused when added. A missing blocker counts as open.
- An unreadable file fails the board read, naming the file, rather than hiding a ticket.
- `ready-for-agent`, `priority:` and `agent:` labels, blocked-by and parents read as on GitHub. `LocalTickets::open_issues` is empty, since there is no triage.
- `shep kelpie ticket new|list|show|edit|close` runs on the files directly (`src/flock/ticket.rs`, `src/flock/verbs.rs`), for the project named or the one the folder holds. It does not check the source, and takes only local ids.
- The worker's prompt carries the ticket's text. Its instructions drop the `Resolves` line (`profile::instructions_for`, `runner/instructions.rs`), so the pull request has none.
- On merge, `close_merged_issue` closes a local ticket in the store (`close_local`, `runner/close_merged.rs`), with the same retries as GitHub's path. It leaves a note on the ticket (`comment_on_ticket`, `Tickets::comment_ticket`), and so does a local parent it closes.
- The review's criteria read a local ticket through `Tickets::issue` like any other.
- `doctor` prints a `tickets` line: `github`, or `local` with the count and folder, missing when the store is unreadable. A local project also gets a `repo writes` line: the branch, the pull request and its comments.
- Follow-ups (`runner/follow_up/`) read the open tickets of the project's source for a duplicate (`open_tickets`), file with `Runner::file_ticket` and comment on a duplicate with `comment_on_ticket`. On a local project a follow-up is a local ticket labelled `needs-triage`, which a person labels ready with `ticket edit`, and a duplicate gets a comment in the file. On GitHub with an App the voice still files and comments. `FollowUpsFiled` lists `TicketId`s.
- A local project writes nothing to its repo but those (#1013). `Runner::local_store` is the project's source as its settings now stand, so a reread moves it, and gates the rest. Each use holds for a work item opened under the other source, since the ticket's id says where it lives:
  - `mark_held`, `make_agent_labels`, `make_priority_labels` and `make_kind_labels` (`runner/claim.rs`) put no label on the repo or an issue. `mark_held` still takes `in-progress` off a GitHub issue held before the source changed, so an item open on an issue across a change to `local` finishes with its label off. A reread to `github` makes the `agent:`, priority and kind labels a local start skipped.
  - `file_red` (`runner/dependencies/`) files a ticket in the store for a red bump it closed, labelled `needs-triage` and `dependencies`, and makes no label on the repo.
  - `post_ruling` puts a ruling with no pull request yet on the ticket, through `comment_on_ticket`. A ruling with one still goes on the pull request.
  - `Settings::check_tickets` refuses `triage.pick` other than `off` at load, so triage never runs. `adopt` returns `AdoptError::LocalStore`, and `labelled_for_adoption` finds nothing.
  - The test double `FakeForge::issue_writes` logs labels made, issues opened and closed, and labels set, for the rig test of a pick-to-merge run.
