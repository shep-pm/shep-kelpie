# Triage taking back hand-labelled issues

The maintainer's hand-labelled `ready-for-agent` issues taken back for triage (#1179). The settings, the pick rule and the verb are in `triage.md`, one issue's pass in `triage-pass.md`.

- `triage.hand_ready` (#1179) takes back the maintainer's hand-labelled `ready-for-agent` issue for every worker. `apply_poll` (`poll_read.rs`) runs `take_back_ready` (`runner/triage/hand.rs`) on the listing, before the due list is made and so before the board's pick in that poll. An issue is taken back when it is open, `Runner::maintainer()` (ignoring case) or the App opened it, after `since` or with `ready-for-agent` on (or taken back from it), it is above `pruned_through` (below it the record of an issue kelpie made ready may be the pruned one), the issue check refused it (`check_owed`, `triage-check.md`), it carries `ready-for-agent` and no triage label but `needs-triage`, it has no record, no work item (open, finished or dropped) and no open pull request whose `closes` names it, and it is not given up on. The record is saved first at `TriageStep::Taken` (state version 82) with `seen` as the swap leaves the labels, `needs-triage` among them. Then `ready-for-agent` comes off and `needs-triage` goes on, and the poll's own listing is changed to match, so the issue is untouched in the same poll and `triage_due` starts its research ahead of the board's pick. A failed swap counts as a triage failure and is tried at the next poll from the `taken` record, doing only the half the listing shows undone, so a stop between the two writes is finished too, and the board may start the issue meanwhile, since the label is its signal. `first_pass_owed` is the due test: no record, a `taken` one, or a finished one the check says was edited since. The first pass seeds its labels from the `taken` record's `seen`, so `triage_labelled_by_hand` does not read the `needs-triage` kelpie put on as a hand label, and the comment it posts replaces the record, after which the ready path puts `ready-for-agent` back and a record at `ready` or `done` is never taken back. A `taken` record is not a finished one, so a prune keeps it. A pull request listing that fails, or is not read (it is read only where a listed issue carries `ready-for-agent` or a recorded `taken` one is listed), takes nothing back that poll, and so does `app_covers()` being false, as `triage_due` starts nothing then and no pass would put `ready-for-agent` back
- An issue that passes the check is never taken back, since it is ready as it stands. With `hand_ready` off, the maintainer's failing `ready-for-agent` issue is still held off the board by the check and triaged, keeping the label beside any `needs-triage` its pass puts on, until an edit passes.
