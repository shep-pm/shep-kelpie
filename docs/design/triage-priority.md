# Triage: the priority

- Every issue a pass labels leaves with a priority. The triager is asked for `P1` to `P4`, never `null`; `Reply::priority` is still an `Option`, so an old reply that says `null` parses. An answer that names none gets `P3` (`FALLBACK_PRIORITY`), the rank that sits behind rated issues and still fills a free slot. The comment says kelpie set it and the maintainer can change it (`Wording::fallback`). Without one the check's `NoPriority` kept a maintainer's `ready-for-agent` issue out, and it waited at `needs-triage` with free slots. `runner/triage/{comment,facts}.rs`
- A priority the issue carries when its pass begins stands, so the fallback is for an unranked issue only (`triage_seen`).
- A pass that asks its author sets no fallback: the answers pass ranks the issue, and a `P3` put on earlier would stand over its rating. An answers pass, or a pass that asks nobody, falls back.
- `P0` is never set. The answer becomes the question to the author (`triage/research.rs`), and where the pass asks nobody the issue gets the fallback so it is not left unranked.
- The label is looked for as `priority: P2`, then the bare `P2` (`board::repo_priority`). `made_priority` makes the board's name where the repo has neither, as a safety net for a label deleted mid-run.
- `Runner::make_priority_labels` (`runner/claim.rs`) makes `priority: P0` to `priority: P4` at the runner's start and on a reread that changes the implementer files or the source to GitHub, for each the repo has under neither name. It only adds, like the agent labels, and a project on the local store makes none. `priority_label` covers `P0` so the maintainer has the label to use. #1493
