# Representative

The agent that words what kelpie says to a contributor, in one voice. Code decides what happens and drafts the facts. The representative only puts them into words. Slices 1 and 3 of #616. #627 posts a local reviewer's pass through this call (`contribution-pass.md`), and the slices after it wire the other posts.

- Agent file `representative.md`, role `representative`, a baseline: `role` and a body, no binding keys, so the operator's file binds it and it runs on any harness as the triager does (agent-baselines.md). `add` writes no file for it, and `agents new representative` writes one that binds it. `crates/core/src/agents/baseline.rs`, `crates/core/src/agents/front/mod.rs`, #869, #1284
- `agents.representative` names it, with no default: unset is refused. `Settings::representative` checks it apart from `role_agents`, so a project with `contributions.pick = "off"` and `triage.pick = "off"` needs no file. `crates/core/src/settings/agents/mod.rs`
- `Runner::open` checks it while `contributions.pick` is not `off` or `triage.pick` is not `off`, and a reread that changes `agents.representative` while either is on checks it as a start does (`runner/reread/mod.rs`). A name with no file, a file that binds nothing, or a file whose role is not `representative`, refuses naming `agents.representative`, as `security_reviewer` does.
- A post that comes late owns the wait. `runner/representative/sorry.rs` works out how many days the thread waited on kelpie or the maintainer before it, as the larger of the reader's last word going unanswered (their newest comment, plus on a pull request the head's `seen`, against the newest comment by kelpie's own login, the App's or the maintainer's, and from their first word where we wrote none) and a promise kept late (a pull request whose open release ask is past `Clock::acts_at`, an issue whose triage ask ran `triage.wait_days` with no answer from the login it asked). `represent_within` adds one fact line naming the days once the count reaches `contributions.nudge_days`, on an issue and a pull request alike, and a thread whose comments cannot be read carries no line and the post goes on. The Sorry rule opens the post with one plain sentence naming the days, before the reply-first answer, with no excuse, no blame, and no promise the facts do not give, at most one per post (`representative-wording.md`). #1967
- One call per post: `Runner::represent(&Post)` in `runner/representative/`. A fresh session every time (never resumed), `Tools::Answer`, no read folders and no fence, so it reads and runs nothing. It runs in `<project>/representative/` and gets no repo plugins or MCP servers: `prepared` gives them to the worker, the reviewers and the project manager alone, since it reads a stranger's text.
- The prompt opens with today's weekday and date, then holds the kind of post (a short instruction from the caller), the facts the caller drafted, the representative's earlier posts and the contributor's text. Under the block naming what the reader wrote, every post is asked to open by answering their words in their own terms, an `ok` taken as an ok and a question answered, before anything from the facts: a post is a reply, on an issue or a pull request alike. On an issue the place line states the whole issue-post rule, and no kind line names a greeting. The thread's first post greets the login the caller's `Opening` names, leads with what kelpie found, and owes at most one plain thanks naming what the author reported, never a stock "thanks for opening this" or "thanks for the report", and never the opener. A post on a thread kelpie has already posted on greets nobody, thanks nobody, and opens with what changed: a later comment that greets again reads as a form letter. `Opening` greets nobody and thanks nobody where the issue is kelpie's own App's, since the App is nobody to greet and its own report nobody's to thank; the login to greet on such an issue is the maintainer's, which `asked_login` gives (#1749, #1960). Earlier posts come as comment ids and are read again through the forge, so edits show. One that cannot be read is left out, and the post is still a later one. Earlier posts and the contributor's text go through `runner/untrusted.rs` as data.
- The call is ended after 15 minutes, and that is a `Call` error, since nothing else holds a synchronous call. The reply is checked in code before it is returned. Every `@login` (also `@org/team`, `@app[bot]`) that is not the contributor's goes in backticks so it pings nobody. Mentions already in an inline code span with a closing run on its line, or in a fenced block that closes, are left alone, and a backtick or a fence that closes nothing protects nothing (a span is paired within a line, because a list item or heading ends one, and a line of three backticks with another backtick after them is a span, not a fence). An email's `@`, and one in a web address are left alone. A backslash before an `@` protects nothing, since a reader may drop it, and an odd run loses its last backslash so it does not escape the backtick. Nothing is refused for its content.
- A failed call or an empty reply is an error to the caller (`RepresentError`), and the caller's own failure rule applies. The pacer is the caller's too.
- Spend: a ledger line under role `representative`, kind `post`, with the pull request, and a `representative` total in `usage` apart from the work items. No work item records it (`crates/core/src/work_item/tally.rs`, `spend/mod.rs`), and no code graph reaches it.
- Harnesses: Claude Code, pi, Codex and goose all run it (`harness.representative` in `docs/parity.toml`). goose's `refuse_unsupported` allows a `Representative` `Answer` call, which with no fence runs in chat mode with no extension.
