# Agent baselines

The shipped agents, baselines, the unbound file and the verbs that write agent files. The agent file and `extends` are in agent-files.md.

- Shipped agents are kelpie's own, embedded from `agents/`; whole agents in `DEFAULTS`, baselines in `crates/core/src/agents/baseline.rs`; files in the folder say only what differs. `extends: kelpie:<name>` resolves to the embedded text, never a file: `:` is not in an `AgentName`, so it never collides with a file, every build uses its own baselines and `--rollback` needs nothing extra. A bare name in `extends` names a file only, no fallback to a shipped agent (`kelpie:nope` names the shipped ones, a bare name with no file says it names no file). #1190, `crates/core/src/agents/mod.rs`
- Baseline from the binary, not `.defaults/`: runners reread files each wake, so one still on the old build during an upgrade would read a new baseline from disk, and a key it does not know stops it. #1190
- `add` writes each missing whole shipped agent as a stub, never over a file. `DEFAULTS` holds only `coderabbit`, `cubic` and `codex`, and no setting defaults to an agent name (#1287). #1190, `src/flock/add/mod.rs`
- The dog loads `agents/` again every `LOAD_TICK` and applies a changed agent to its board and availability with no restart (dog-settings.md). A folder that fails to load keeps the old agents.
- `agents/.defaults/<name>.md`: every shipped agent whole, mode 444, first comment says kelpie writes it and to override in `agents/<name>.md`. For reading and diffing, nothing loads it (the loader reads only `.md` files directly in `agents/`). Written by `add` and by the dog's start, so each upgrade's restart refreshes it, removing a file kelpie no longer ships; replaced by rename of a temp file each writer creates new (pid and a number, the next free one), removed on failure, so a read never sees half and two refreshes never share one; a `.tmp` a minute old is a crash's and the refresh removes it; on Windows the target's read-only flag is cleared before the rename. #1190, `write_baselines`, `crates/dog/src/dog/mod.rs`
- No hash tracking and no `doctor` line for a body that replaces its baseline's. #1190
- Baseline = a shipped file with `role` and a body, no binding keys (`harness` `model` `effort` `second_look` `usage` `url` `gateway` `context` `tools`); binding = those keys, in the operator's file. The seven baselines (defect-hunter standards spec security-reviewer pm representative triager) carry none (#1284). A baseline that carries its binding keys resolves with no file: `Agents::embedded()` holds it beside the whole agents. One that binds nothing is kept out of the book and listed by `Agents::bare_baselines()`, so the refusal below tightens by itself. `extends: kelpie:<name>` resolves in both lists. #1232, #1282
- Unbound = merged frontmatter has a `role` and no `harness`. The loader leaves it out of the book and keeps it in `Agents::unbound()` (name, path, role), so one stale stub stops no project that never names it. `find` refuses a name that is unbound, or the name of a baseline that binds nothing and has no file, with `shep kelpie agents new ...`; `doctor` gives one `missing` line per unbound file (`src/doctor/unbound.rs`). #1282
- `write_defaults` (so `add`) writes stubs for whole agents only; `.defaults/` still gets every file. #1282
- `agents/models.toml` (#1232): kelpie's own models file, embedded with `include_str!`. Harness, then role, then `model` and `effort`, with `second_look` and `context` where they apply; a role with several baselines names each one, and its file is named for it; `order` is the harnesses `--detect` prefers. Only the claude-code rows ship, copied from `legacy::TABLE`. `core/agents/init.rs`
- `agents init <harness>` writes a bound file for each row of that harness, never over one, kept ones named; a role the harness cannot serve is skipped, naming what it lacks (#1285); a pi or goose row needs `--gateway` or `--url`. `--detect` takes no harness or flag: `Host::on_path` per CLI, `flock::gateways` per gateway's models, each role to the first in `order` found serving it. `src/agent_verbs/init.rs`
- A runner with no implementer to pick is refused at start and at a reread, naming `agents init`. `Settings::require_implementer`, `crates/core/src/settings/agents/mod.rs`
- `agents new <role>` (`src/agent_verbs/mod.rs`) writes `extends: kelpie:<baseline>` + binding keys, or `role: implementer` + them (`--name` required, no baseline). Text is read by `baseline::check` (the loader's merge and parse) before any write, so a refused binding writes nothing; the loader's harness refusal names the harnesses meeting the file's needs, other errors keep their own; writes over no file but an unbound one, keeping its body and other keys (and its `extends`/`role` when no baseline is chosen). `agents list`: agents, unbound files, baselines that bind nothing and have no file. #1282
