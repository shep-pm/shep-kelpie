# CI and the merge

CI, catching the branch up, the merge, work after it. Review passes, bots and rulings are in review.md, and `main`'s own CI in main-ci.md.

- Red CI whose failed logs (read as the maintainer's login) name no file the branch changed: kelpie reruns that head's failed jobs once (`gh run rerun --failed`), no fix turn, `reran` on the item, `rerunning` in `status`, `ci-rerun` in the log. Unreadable log, a changed file named, a refused rerun, a rerun head, or a run its `timeout-minutes` ended: fix turn as below, saying the failure repeated after a rerun. #648, `runner/gate/rerun/`
- A head with no check goes on as `Checks::Skipped` when no `origin/main` workflow runs on a pull request, else parks `no-checks` past `ci.queued_minutes` (a yes passes that head). `runner/gate/queued/none.rs`, ADR 0008. #1194
- A check run stuck `QUEUED` or `IN_PROGRESS` on a finished run is rerun whole past `ci.queued_minutes`: stuck-checks.md. #1164, #1249
- A `still-red` ruling raised when the failed logs name no changed file (and are readable) offers a Rerun option: choosing it reruns the head's failed jobs once more and returns to CI, whoever chose it (`rule <id> rerun`, the project manager's answer). Not offered, and refused, when a log names a changed file or a timeout ended a run. A `turn-failed` ruling holding uncommitted changes to agent files (`.claude/`, `CLAUDE.md`, `AGENTS.md`, or any file the fence refuses) offers Restore: kelpie checks them out of `HEAD` (a new file is removed) and resumes the turn. Each shows in the board's events with its option. The experts stay read-only. #710, `runner/ruling/act.rs`
- After review item waits for CI; red = fix turn; second red on untouched head parks `still-red`, and a yes returns to the review round the red run interrupted, else to CI; `ci.fix_attempts` caps fix turns (`-1` no cap). `ci.block` off reads no checks. Each head read red is counted once in `kelpie_ci_failures_total`, and the work item's record of the head it counted holds across a `still-red` yes (`metrics-work-items.md`). #9, #380, `runner/gate/`, `runner/ci_failure/`, `crates/core/src/settings/ci.rs`
- Branch behind `main` caught up by kelpie: rebase with lease, or merge where commits aren't kelpie's to rewrite. Conflict: kelpie starts `git merge --no-commit origin/main` in the worktree itself (so `main`'s files the sandbox refuses, `.claude/` included, land staged), and the worker turn only resolves the conflicted files, `git commit --no-edit`s and pushes without force. A rebase that conflicts falls back to that merge; a merge with no conflict is committed and pushed. A worktree already mid-merge is not merged again; unresolved parks `rebase`. It also runs from a review whose head has no checks once they settle, and returns there, not to CI, also on a yes to the `rebase` it parks. #61, #609, #1163, `runner/gate/catch_up.rs`
- `main` reaches a worker through kelpie and never its own fetch: `worktree::prepare` fetches `origin/main` before every worker turn (a fetch that fails keeps the ref kelpie last got, and `runner::turn::worker_reach` stands a warning `status` lists until a fetch lands or the item ends (`runner::merge::cleanup`); the gate fetches again), and `kelpie guard` answers a `git fetch`, `git pull`, `git remote update` or `git remote prune` that reaches the item's repo with `git merge origin/main`, since in the shared `.git` a worker may write only its own branch's refs (git searches upward for a repo, so a folder kelpie cannot follow, or one the call made inside the worktree, reaches it too; a fetch git is pointed at another repo by `--git-dir`, `--work-tree`, `--bare` or a `GIT_` assignment is left to git, since kelpie cannot tell which repo it names). A `Start::Main` branch starts on that ref, so there a failed fetch is an error. #950, `crates/process/src/worktree/mod.rs`, `runner/turn/`, `crates/core/src/guard/git/mod.rs`
- `git.merging` required: `auto` or `ask`. `ask`: yes merges only the head asked about while green and current, `--merge --match-head-commit`, never squash. `runner/merge/`
- `auto` replaces only the merge ruling; unreviewed passes, open threads, unread heads, unread fixes still raise it. Merge no longer valid returns to CI; second forge refusal parks `merge-refused`. One webhook notice per auto merge. #83, #118 A head carrying commits of other open pull requests (a fork's apart: the head shares a commit with its branch that `main` lacks, even where the branch has moved on) raises it too: its question names each pull request, draft or not, and the findings held by the work item that has it, else that kelpie holds no record. A yes merges as before. #1444, `runner/gate/borrowed.rs`
- Merge queue holds the PR, kelpie skips gates meanwhile; removal goes back to worker like red CI. #213, `runner/merge/queue.rs`
- Head, label or ready state kelpie didn't set parks `foreign-change`; its yes gets a review pass. #69
- PR merged by hand ends item; closed unmerged parks `closed`. #377
- After a merge, the item's parent closes (App comment names the PR) once no sub-issue is open and one was built; all not planned stays open; one level up only; failures logged. #640, `runner/close_merged.rs`
- Rework reopens a kelpie PR on `ready-for-agent` or requested change (author can't request changes on own PR); fresh start, never force-push. #53
- Adoption: work item from a PR kelpie didn't open; merges `main` in, never rebases (owner may push). #84
- `ready-for-human` set at merge ruling, removed when work resumes. `runner/ruling/`
- Runner's own git/gh are plain children outside any worker fence. `crates/process/src/spawn.rs`
- One pass lists the open pull requests once (a GraphQL query: head, draft, checks, check suites, labels, closing issues, review and thread counts). A failed workflow run with no check run (an unreadable file) fails as `<path>: started no job`; a lone read asks for suites on a green rollup. Rework check, CI gate and merge read that listing; one pull request is read alone only when the listing lacks it or a step runs outside a pass (a turn's end). A review is read in full only on `ready-for-agent` or when its counts changed since the last read; merge reads run off the lock; the forge refuses a moved head. #581, `runner/snapshot/`
- A maintainer's yes to a merge ruling vouches for its head, so kelpie's catch-up with `main` before the merge carries the vouching and raises no second ruling; a no or a rework vouches for nothing. #668
