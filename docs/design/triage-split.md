# A split the triager planned, and filed

What the triager's `split` answer becomes: the plan saved, asked of the maintainer, and filed as sub-issues. The rewrite and the ready path that hand it over are in `triage-ready.md`, the pass in `triage-pass.md`, and the check every draft goes through in `triage-check.md`.

- The triager judges size itself and answers `split`, a list of `{title, body, priority, kind, after, agent}` (`research::Drafted`), with the project's implementers in the prompt (`implementer_files`). `readiness` turns it into `Ready::Split` and saves it as the plan in `record_triage`, one commit with the record. Only `own_author`'s issue keeps its rewritten body: from anyone else no body is written and the drafts come as `Ready::Ask` (#1847). Every saved plan waits for the maintainer's yes before a draft goes, the maintainer's own issue included (#1978). The parent's `body` is checked like a draft, and a draft's `agent` becomes `agent:<name>!` through `agent_label`, an unknown name refusing the split. A named family is one picked agent and an `Assumed:` line. A draft or parent that fails the check or names a path on this machine (`self.local.find`) gives `Ready::SplitRefused`: nothing is filed and the comment says why. A draft with no priority takes the one the issue carries, else the triager's. The parent gets the pass's kind and priority labels before its drafts are filed. A pass that ends with no body written (a refused or moved body, a hand label) takes back a plan with nothing filed (`unplan`). No redraft. `runner/triage/{research,ready,split,facts}.rs`
- A saved split (`TriageState::splits`, a `TriageSplit` per parent: `drafts`, `from_issue`, `filed`, `asked`) is filed in place of `ready-for-agent` where `label_ready` finds one, so `body-written` stays the retry point and no step is added. `split_refusals` runs the issue check over every draft first, and a failing draft files none: `notice_on` names the draft and why, the record ends `done`, and the parent stays with its entry. `asked` set holds the filing with no failure counted. A parent never gets `ready-for-agent`: `check_passed` leaves it, and the labels it carries come off before the first draft goes. State version 103, and 106 for `from_issue`. `runner/triage/split.rs`
- No split files on kelpie's own word, whoever filed the issue: only the maintainer's yes starts git work, and the gate is code. `plan` saves it held, with `asked` set to the triage comment, which no reply can be to. `ask_held_split` puts `needs-approval` on the parent and `ask_split` posts a new comment naming `maintainer()` once the pass ends, and `asked` holds that comment; `ask_posted` tells the two holds apart, so `split_waits` counts only a posted ask and `unplan` keeps a plan whose ask is up. The ask says every draft passed the issue check, and asks by who filed the issue: on `own_author`'s, to confirm the split is what they meant; on anyone else's, to approve the split and the directions its author gave. It also names whose split it is: `from_issue` is true when the issue itself spells the split out and the triager followed it (its reply's `split_from`, `issue` or `kelpie`), and the ask says so. The ask ends in a marker keyed to the triage comment, so a post whose answer was lost is found and not made again. A pass that ends by a hand label drops the plan it never asked, and `TriageState::prune` keeps the record of a held plan. `triage_waits` includes it, so `thread_job` reads the thread and `hear_triage` hears it from the maintainer's login alone (`their_replies` takes the issue and the login). `says_yes` reads a reply that is only `yes` or `ok` and clears `asked` and steps the record to `body-written`; `no` drops the plan, other text leaves the wait open, and silence `triage.wait_days` drops it with no App needed. `label_split` asks a held plan and files nothing while `asked` is set. A pass that stopped with `needs-approval` on the parent and no ask up leaves that label as the labelling step's own (triage-ready.md), so the next poll asks again rather than reading it as a hand label and dropping the plan. Naming the login the ask mentions is retried the same way: `maintainer()` asks the forge when the settings name none, and a call that failed leaves the plan held under `needs-approval` with the record at `body-written`, tried again at the next poll; only once the issue's triage tries run out (`triage_given_up`) is the plan dropped as one with no maintainer to ask. State version 106. `runner/triage/{split,split_ask}.rs`
- Per draft, in order: its labels made (once an attempt), `file_ticket` with `Slice <n> of #<parent>.`, one `Blocked by:` line (the `after` drafts and the body's own) and a last line `<!-- kelpie:split <parent> <index> -->`, `filed` saved, `add_sub_issue`, `add_blocked_by`, then `ready-for-agent` last. One `open_issues` read an attempt finds a body filed before a lost answer by its marker, so a retry files nothing twice. A restart relinks the last filed draft, since the links and labels are idempotent. A busy forge retries at the next poll, a hand triage label ends the filing, and `triage_busy` leaves a child alone until its parent's record ends. An entry goes when its issue leaves the listing (`settle_splits`). A start or reread that turns triage off, as a local ticket source needs, notes each split left part filed (`split::stopped`). `runner/triage/{split,checks,poll_read}.rs`
