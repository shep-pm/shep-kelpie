# Review pick

How a pass chooses each round's reviewer. The pass it sits in is in review.md.

- Each round asks the agent board (`board_picks`) for a reviewer: the item's kind, tier and slack, no pin, as candidates every reviewer file `agents.allow` holds but `contributions.security_reviewer` that can run (`paths`, a down local, a bot's `rounds`), and the pass's reviewers left out, with every bot the project left out as one its repo cannot run within the last 7 days. It takes the first ranked one the pacer lets start (`Scope::Turn`) and, for a bot, whose window is open now; a held one or a bot with a closed window is skipped, not waited on, and a bot is passed over (`bots_skipped`, so a late review is still read). A board that cannot be reached leaves the round to ask again next poll, with no fallback. A reviewer counts toward the reads its item calls for once its round ran, not a bot passed over or a reviewer that kept failing. The pass goes to CI at those reads or when the board ranks none left; every held one waits on the first hold. ADR 0018, #1539, #1541, `runner/review/lineup/mod.rs`
- A board that ranks none of the candidates that could run, with nobody having read, marks the item `unreviewed` (a ruling, not CI and an auto merge): a tier no reviewer file fits or a file the board does not know yet cannot send a pull request through unread. A bot kelpie itself left out is none the board was asked to rank, so the reason names it as left out with when it comes back. After a read it only ends the pass. `runner/review/lineup/mod.rs`
- The start's, the reread's and `doctor`'s checks (a local reviewer that does not answer, a review bot that has never reviewed on the repo, a reviewer on a gateway kelpie cannot route) hold only the reviewers `agents.allow` names, and a reread runs them when the naming changed or a named reviewer's file did. A named CodeRabbit on a repo that is not public is no refusal: the start and the reread log one line and go on (the reread when it newly names it), as for an implementer no turn can run on. It stays a candidate whose round is passed over as not public, as an unnamed one is, and `doctor` still names it. Reading the repo's visibility is only ever that line, so a read that fails logs one and keeps CodeRabbit a candidate, at the start and at a reread alike. A candidate it named no is passed over at its round, by the repo's visibility or as down, and one on a gateway kelpie cannot route is no candidate at all. A reviewer, named or not, whose gateway key the runner lacks is left out of every round and logged once (`reviewer <name> is left out of the agent board's ask: <reason>`) at the start and at a reread that newly leaves it out, as an implementer is. That is a missing key only: a gateway kelpie's settings lack is a settings error, and it stops a project that named the reviewer. `runner/reviewers_check.rs`, `settings/reviewers/mod.rs`, `doctor/project.rs`. #1544, #1757
- `choose_reviewer` weighs the diff each round (`Runner::weigh`, saved as `WorkItem.weight`, state file version 96, 97 with `Heavier::High`, and 98 with `Lighter::Pm`) and only reports what it touches: on a project that names `agents.pm` it weighs every item whatever the diff, and on one that names none it weighs nothing, so `status` shows that project no weight line. It reads `light (docs only)` when every changed file matches `LIGHT_PATHS` (`["**/*.md", "docs/**"]`, a const in `runner/review/lineup/weight.rs`) and `full (…)` otherwise. Always full: an adopted item, an empty diff, a workflow file under `.github/workflows/`, a lockfile or manifest of a `package_managers::MANAGERS` entry at any depth, and a harness's own file (`fence::owner`). `after_round_in` weighs the worktree again first (`reweighed`), so a fix turn that pulls a docs-only change into `src/` or a manifest is reported full, and a diff git cannot take leaves the stored weight and the pass in review, so the next round's `choose_reviewer` reports the failure instead of a stale light weight ending the pass. No flag is stored: the weight is read from the diff each time, and a review bot's threads are not read for severity. `changed_lines` (added plus deleted from `git diff --numstat --no-renames` over every changed file, the same range as `changed_files`, which reads names with `-z` so a non-ASCII name is not quoted before the globs see it) goes out with a round's findings as `Wake::Findings`' `lines` and weighs nothing. `Heavier::FullPaths`, `Heavier::High` and `Lighter::Pm` stay as weights a state file saved before the review plan went to the project manager can hold, so `VERSION` stays; kelpie writes none of them, and no finding steps a weight up. The ask takes `item.tier` on every project, so a light weight lowers no tier. The fix turn, local rounds, review bots and `contributions.reviewers` are untouched. #1676, #1677, #1680, ADR 0020, #1765, `runner/review/lineup/weight.rs`, `core/work_item/weight.rs`
- The count a pass reads is `need_of`: the item's `review_plan.reads` when the project manager planned one, else `RULE_READS` (2) on an adopted item, since a stranger may have written it, else one read on a project that names `agents.pm`, which plans its reads, else `RULE_READS`, kelpie's own rule for a project with no project manager to plan one. An item no pick planned (the board rule's pick, `add`, a rework) thus reads once under a project manager and twice without one. `Runner.rule_reads` holds the rule from open, and only the rig sets another. While a round's ask for one more read is out, `choose_reviewer` gives `Begin::Idle` (`review-more.md`). ADR 0020, #1764, #1765, `runner/review/lineup/weight.rs`
