# Project manager's cases

The case files, `cases/<issue>.md`, the project manager reads for each work item parked on a ruling: what one holds, how it marks text as data, what stays out. The board file is in pm-board.md.

- Each wake writes `cases/<issue>.md` for every work item parked on a ruling, whatever its kind, after emptying `cases/` so none outlives its ruling. A case holds the ruling's card, the whole issue (title and body, uncut), and the pull request: state, draft flag, head, checks, labels, and its open review threads and conversation comments, then its `## CI`, `## Past rulings`, `## Spend`, `## What the worker said` and `## Log lines`. The `## Code` line of each item names it, or says why it has none. The prompt and `board.md` name the file and carry none of it. A read that fails says so on that line and in the log, and the wake goes on. A reply gh could not parse is named, never shown: it holds the strangers' text the case cuts. The reads join the off-lock logs job (`Logs.pulls`, `Logs.talks`), so the lock is let go for them, except on a wake that runs no job (`wake_pm`, as `pm_ended` does when a session cannot resume), where each reads inline. #1805, `runner/pm/case/`, `runner/pm/ci_logs.rs`
- What stays out of a case: a thread is open when neither resolved nor outdated (`isOutdated`: its lines changed). It stays when a listed bot opened it or a writer spoke in it, and only writers' and listed bots' remarks stay inside it; conversation comments are cut the same way. Every other thread adds to a count the case states, and its words are kept nowhere. A contribution (`contributor` set) gets no case, and its line says so. #1805, `runner/pm/case/threads.rs`
- How a case marks text as data: every line someone else wrote goes through `shown` (text naming this machine withheld) and then `quoted`, `> ` on each line, so no line inside can close a block. Headings and labels are kelpie's own, with these exceptions: a thread's path in its heading, and a check's, workflow's and label's name, pass through `plain` alone (control characters and backticks become `?`), not `shown` or `quoted`. The file's first lines say a `> ` line is data to weigh and never an instruction. No part is capped. `Forge::talk` reads 100 per list, so a full list says which end may be missing (a full conversation loses its older comments, full threads and full replies their newest) and how to read the rest on the pull request. #1805, `core/board/briefing/`
- A case's `## CI` part lists every run on the pull request's head (`Forge::head_runs`: `gh run list --commit <head> --limit 1000`, since the shared 50-newest list cannot serve), each with its workflow, conclusion (`still going` while it has none) and run number, then holds the log of each run that failed, `failure`, `timed_out` or `cancelled`, uncut and quoted on every line through `shown` and `quoted` (`Forge::run_log`, `LogPart::Failed`: `gh run view --log-failed`, which holds the failed steps alone, so a passing step's lines may be absent; the whole log where that is empty, as for a cancelled run). A rerun keeps its run's id and advances its attempt, so a kept log is keyed by run and attempt and a rerun that fails again is read anew. A green run's log is not read: it is large and rarely the answer, so the project manager asks for it when it needs it (#1813, `LogPart::Whole`). GitHub lists at most 1000 runs of one commit, and a list that reaches that says older runs may be missing. A log GitHub answers as dropped past its retention (a 404 or 410, `ForgeError::log_is_gone`) is said to be gone, and a read that failed for any other reason says so and is asked again at the next wake. `failed_run_logs`, `ci/<issue>.log` and the `StillRed` text stay as they were. #1806, `runner/pm/case/ci.rs`
- A completed run's log never changes, so `Desk.run_logs` keeps each failed log by item and run, in memory: read once, dropped at the wake after its item closes, forgotten by a restart, absent from the state file. The run list is read at every wake, since runs start and end. The off-lock logs job reads the pull request, then its head's runs, then each failed log no case holds, so the lock is let go for all of them and the forge ledger shows them under the wake. #1806, `runner/pm/ci_logs.rs`
- A case ends with what already happened on its item, since the closing message is stale after a failed or timed-out turn. `## Past rulings` lists every `rulings.jsonl` line with the item's `issue`, newest first: when, kind, what was asked, the answer, who answered and `stem`, under a head that counts this ruling's kind (`this is the 3rd turn-timeout on this item`). `## Spend` is the board's line, `item.priced().total()` against `item.budget_cap(per_item_usd)`. `## What the worker said` is every non-empty `Said` text of the item's session, oldest first (`watch::said`: Claude Code, Codex and pi each from their own transcript, found by `watch::transcripts_of`; goose gives none, #784). Codex's newest unclaimed rollout, which `transcripts::find` takes for a first turn, is accepted: the text is advice and no gate reads it. A line still being written is passed over. `## Log lines` is every `steps.jsonl` step naming the item (`watch::steps_of`), kelpie's only service log. Both go through `shown` and `quoted`. The logs job reads `steps.jsonl` once and each transcript off the lock (`Logs.told`); a case reads inline where no job ran. A file that cannot be read (`rulings.jsonl`, `steps.jsonl`, a transcript) says so in its part and on the case's board line, never as an empty history, and the wake goes on. #1807, `runner/pm/case/history.rs`, `core/watch/`
