# Who answers a ruling

Who answers a ruling: the maintainer, or the project manager for the kinds `rulings.pm_decides` gives it. Posting rulings as the App is in `github-app.md`. The ruling panel that voted on rulings is gone (ADR 0018); `docs/facts/the-panel.md` keeps what it measured.

- `rulings.pm_decides`: map of every kind, `true` = PM answers, `false` or absent = maintainer. Defaults in `RulingName::pm_default`: `question`, `foreign-change`, `agent-files` and `agent-fit` `false`, the rest `true`. `true` refused for `merge` (one voice must not merge), `security` and `contribution-merge` (a stranger's text must not reach an agent that answers it) and `local-model-spilled` (gone). `add` and `settings migrate` (run by `upgrade`) write missing kinds; old `pm_alone` list loads one release as `true`, both refused. ADR 0018, #466, `crates/core/src/settings/rulings.rs`, `src/flock/set/migrate.rs`
- `agent-fit` (ADR 0018, #1546): after each `finished` line naming an agent and a kind, the runner asks `AgentBoard::fit` about that pair, and a finding raises the ruling on that item's pull request. It parks no work item, as a contribution's does, and a ruling already waiting under that number keeps its place. Its card shows both records side by side and the `kinds` line the board suggests for the agent file. A yes and a no both change no file: kelpie never writes an agent's `kinds`, so an answer only clears the ruling, and the dog marks the pair so it answers the same one again only after `FIT_AGAIN` more items. A finished line with no agent or kind, an item with no pull request, and a board that cannot be reached all raise nothing; the next finished line asks again. `runner/agent_fit.rs`, `runner/ledger.rs`, `core/state/ruling.rs`
- A ruling of a `true` kind with 2+ options, with `agents.pm` named, wakes the PM with `Wake::Answer` (`pm_asked`, on the save that raises it) and its comment waits on that one wake, as a question's does (`pm.asking`, `Ruling.unposted`). Every other ruling posts to the maintainer at once. A question and a follow-up keep their own wakes, whatever their value. `runner/pm/rulings.rs`
- Never the PM's: a contribution's ruling, a turn kelpie could not set up (`TurnFailed { setup: true }`, the fix is on this machine), a ruling raised in a drain, and a failure the PM already answered on the same work item (`Record::decided_by_pm`, `why` compared with its whitespace collapsed), since that answer did not fix it. #1250, #1368
- The answer is the `votes` key, one `{"ruling", "choice", "why", "design"}` each (`crates/core/src/pm_answer/`). A choice that is an option is applied through `Settler::Pm` and posted headed "Answered by the project manager: A, <option>"; `<id> no <note>` there reopens it within 24 h while its work item is open and its worker not running (`threads.decided`, `watch_decided`). #466
- To the maintainer instead, with `**Project manager: A**. <why>` on the card: a `design` flag, a merge under `git.merging = "ask"`, a pick only the maintainer can carry out (`Ask the maintainer`, an option that begins "You"), a pick that is no option, or an answer that cannot be applied. No answer, or a wake that failed, posts the ruling as it stands. The PM's pick is kept in the ruling's question as `PM recommends:` / `PM says:` lines, which the card reads.
- A ruling left to the maintainer wakes no PM until they reply in its thread (`runner/pm/asked.rs`, `Wake::Answer { request }`, `pm.asking`): `<id> pm recommend` posts its pick there as `**Project manager: A**` with the reply that gives it, still theirs; `<id> pm options` posts up to 5 other approaches, each `inert`, kept as `Ruling.approaches` (state file 88), and `<id> pm <n>` takes one as their `no <note>`, or a question's answer, raw; `<id> pm decide` hands it over as if its kind were `true`, refused for the kinds `true` is refused for and the never-the-PM's above. No `agents.pm`: all refused. A second request while its wake runs is answered once; a wake that fails or gives no answer says so in the thread. ADR 0018
- Question listing under 2 options: the PM's question wake drafts 2-3 `candidates` (one may be `Ask the maintainer`), which become its `- ` options for the maintainer. Question text stays as asked; free text still answers. No PM = no candidates. #709, `runner/pm/question.rs`
- An option can name an action kelpie runs in code when chosen (rerun, restore). See merge.md. #710
- An answer, or a ruling's note, is the worker's next turn. A resume its harness finds no session for (`NoSession`) starts over once with the same id: the item's brief, then what the lost resume was to send, so the answer still reaches the worker. `runner/turn/mod.rs`
- Each answer is a line of `rulings.jsonl` (`runner/ruling/history.rs`), by the maintainer or the PM; `status` counts the PM's answers by kind (`pm_answers`). A line an older build wrote reads; one the panel decided is skipped.
- What the panel left: the state file (87) drops a ruling's `panel`, `verdict` and `skipped` on load; the usage ledger's old `vote` lines still read, their kind kept by name (`LedgerKind::Retired`), and count where their role does; `settings migrate` deletes `rulings.decide` and `rulings.full_panel_paths`, which the runner refuses.
- The panel's experts went after it (ADR 0018): `Role::Advisor` and `Role::Researcher`, their tools, agent files and baselines, the researcher's web on every harness and its packages. `agents.advisor`, `agents.researcher`, the `researcher` table and those two values in `repo_setup.roles` are refused by name, and `settings migrate` deletes them (`src/flock/set/migrate.rs`); `agents migrate` deletes a stub of either baseline holding only its binding and names any other (`agents/legacy.rs`); `write_baselines` removes a `.defaults/` file kelpie no longer ships. Ledger lines of either role still read (`LedgerRole::Retired`) and count in `shep kelpie usage` on one `retired roles` line naming each, and in the loaded figure. No state field held either role, so the state file has no step.
