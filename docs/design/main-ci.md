# Red workflows on `main`

The runner's read of `main`'s own CI, apart from a pull request's. Part of CI in merge.md.

- Red workflows on `main`: the runner reads the latest completed run of each workflow on `main` (`branch_runs`, the 50 newest runs) at most once per `MAIN_CI_POLL` (15 minutes), with the failed-step backoff on a failed read, whether or not `ci.block` is on. `pull_request` runs are ignored: a fork's own `main` carries the name. The read runs at the start of every pass with the lock let go, unless the forge is held. State `red` keeps each red workflow: the first red run read since it was last green, the latest red run and head, and when that first run was created. `failure`, `timed_out` and `startup_failure` are red; `success` clears; `cancelled`, `skipped` and the rest change nothing. While anything is red the same read lists the repo's workflows (`workflows`, `gh workflow list --all`) and drops a red one missing from the list or not `active`, since a workflow that cannot run again would stay red for good; an active red one stays red past the 50 newest runs, as a nightly one does until it runs green. A failed list is a failed read. `status` (`red_workflows`, with `red_for` and a run link) and `board.md` (`## Red on main`) list them. #702, `runner/main_ci/`
- Each new red head of a workflow on `main` has its failed jobs rerun once (`rerun_run`, `gh run rerun --failed`; `reran`, `reran_head` on the entry). A head red again after its rerun, or whose rerun was refused, is `again`: the PM's to fix or ask about (`pm.md`), and the first such read of a stretch queues one webhook notice (`noticed`): workflow, run link, how long red, the last 20 lines (2000 bytes) of its failed log. A used-up rate limit waits for the next read. A new head clears `again` and `handled`. Green after a notice queues one green notice; a passing rerun, or a deleted or disabled workflow, tells nothing. A run older than the stretch's first run, or with a lower id than the run rerun, is ignored (the rerun's run is not completed, so an older one shows). The notice takes the merge notice's path (`runner/alert/`: after pending rulings, same backoff, logged only with no webhook). #703, #1183, `runner/main_ci/`
