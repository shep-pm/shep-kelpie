# Browser dev server

A worker's sandbox binds no port and a headless turn has no background tasks, so kelpie starts the project's dev server for it. `runner/dev_server/`, `crates/core/src/ports/dev_server.rs`, `crates/adapters/src/adapters/dev_server/mod.rs`

- It starts before each worker turn that has the browser, from `.claude/launch.json` as `origin/main` has it (`git show`, never the worktree, so a worker cannot widen its own sandbox). `browser.configuration` names one, else the first. Fields read: `runtimeExecutable`, `runtimeArgs`, `port`, `cwd`, `autoPort`. No file on `main` starts nothing. `runner/dev_server/launch/`
- `cwd` resolves under the worktree. One that leaves it by `..`, an absolute path or a link is refused, and the instructions say why.
- Its own `srt` `Policy`: writes the worktree and build folder under the fence's `no_write` and `no_read`, reaches `browser.domains`, `listen: true`, `services: ["com.apple.FSEvents"]`, the keychain blocked as the call's is, and `NODE_USE_ENV_PROXY=1`. `TMPDIR` is `dev-server-tmp` in the build folder, made when the plan is, since a sandbox refuses `/tmp` and a sheep has no `TMPDIR`; the worker's `build_env` is set too, so the server shares the caches its worker's tools use. The variables reach the server through `env`, not the sandbox runtime, whose proxy socket sits under its own `TMPDIR` and which a path past 104 bytes keeps from starting.
- A worktree with no `node_modules` has its packages installed in the server's sandbox first, as a bump's checkout does (`dependencies.md`): the lockfile's folder is installed from the frozen lockfile when it holds no `node_modules` or an install left `install-unfinished` in the build folder (written before the install, removed when it succeeds, so one cut short runs again), and the server gets 300 seconds to answer instead of 60. Each folder the plan's env names in the build folder is made when the plan is, a `build_env` entry included (`fence-install.md`). Without that, `bun x vite` fetched vite into a temp folder the sandbox refused (`error: bun is unable to write files to tempdir: EPERM`) and the worker shipped with no browser check (#1221). A work item's worktree is installed the same way before its first turn (`fence.md`), so this install finds `node_modules` and skips. `runner/dev_server/install/`
- Port: the configured one when free and not planned for another work item, whose server may not have bound it yet (port 0 is no port: it is replaced, else the turn runs without a server). Whether a taken port is replaced is `autoPort`: `true` always, `false` never, and absent where the project has room for more than one work item (`concurrency.active_items` above 1), since those items share one configured port and only the first would otherwise get a server. Where kelpie picks, it sets `PORT` and replaces the configured number where it is a whole `runtimeArgs` entry. A taken port that is never replaced runs the turn without a dev server, and the instructions say so.
- A port taken between the plan and the start refuses the start. Ready when it answers on its port while the server kelpie started still runs, 60 seconds at most (300 where it installs packages first). Only then does the browser's `DevPort` gate open that port (filter and proxy both read it), and it shuts when the turn's server is dropped. A server that has not answered leaves the port shut. If it never answers the turn still runs, and the instructions name `dev-server.log` in the build folder.
- It is a child of the runner in its own process tree, stopped (TERM, then KILL) when its `Started` guard drops, whatever ended the turn (ADR 0005).
- The plan is made under the runner lock and lasts until the turn ends, so a retry reuses its port. The start and wait run on the call thread, off the lock.
- A resumed session does not re-read its instructions, so news that the server is down goes in that call's prompt. A new session gets it in the instructions, where a standing line points to the log.

The browser it serves: `docs/design/browser.md`. Measurements: `docs/facts/the-browser.md`.
