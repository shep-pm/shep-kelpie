# Work

Projects, slots, the issue check. The board and work items are in `board.md`, the project manager in `pm.md` and its board in `pm-board.md`. `start`, `pause` and `finish` are in `runner-start-stop.md`.

## Projects

- `shep kelpie add`: registers stopped runner + `[app.dogs.kelpie]` table; takes `--base`, writes `git.base`; reads all, then makes only what's missing. `src/flock/verbs/`, `src/flock/add/`
- `add` refuses a checkout or repo another project's table names, even a broken one (two runners, same issues). `src/flock/add/`
- `tell --all "<note>"`: the note to every project's project manager in name order, on the one `Reach`, so the socket-first fallback is said once for the command. A runner that is stopped, or refused the note, lands in `refused` with its reason and the rest are still told; the verb prints the told lines and then fails. `tell` reads `--all` only as its first word, and `split_project` counts the words a `--` left before it, so a note holding the word later, or after a `--`, keeps it; `--json` is read the same way. A stopped runner is sent nothing. `src/flock/control/tell_all.rs`
- `get [<key>]` prints the project's table or one dotted key; `set <key> <value>` reads the value as TOML (else a string), checks the whole result as a runner start and reread do (settings, agents, reviewers, rulings, gateway shapes with no key read, skills; and for a moved `git.checkout` or `git.remote`, the checkout and `add`'s one-runner-per-checkout-and-repo rule), and only then writes the table back; refusals write nothing. A table written another way (lookout, `shep copy`) gets the same checks at runner start (refuses, exit 78) and reread, and a refusal alerts. Says whether a running runner takes the change at its next wake or start. Not `[kelpie]`. #273, #965, `src/flock/set/mod.rs`
- A review is the maintainer's when a `User` left it, it is not `PENDING`, and its `authorAssociation` is `OWNER`, `MEMBER` or `COLLABORATOR`, or the author's permission on the repo is `write`, `maintain` or `admin` (`repos/<repo>/collaborators/<login>/permission`, through the same login as the read). The App reads a private organization member as `CONTRIBUTOR`, so the association alone drops their reviews and `rework` answers "nothing to rework". The permission is read once per login per `Forge::reviewed` call, only for a review the association passes over; a refused or unreadable read, or `read`, `triage` or `none`, leaves it uncounted, while a rate limit, a hold or a `gh` that cannot start is returned as the call's error. #1615, `adapters/gh/review.rs`

## Slots

- `concurrency.active_items` (1): a project's slots, each item own branch + worktree (a parked PR must not hold the project). #103, `runner/slots.rs`
- Slot bounds model calls only: parked or `Done` item frees it, model-free phases slotless; one needing a model again goes before new work. A call on a followed contribution takes one too, before new work (contribution-security.md). #355, #621, #1162, ADR 0007
- `concurrency.pending_rulings` (2): no new work while that many items parked (alerts can't open PR after PR); `add` ignores it. #355
- Issue naming a file a parked branch changes skipped as `overlap` (ruling may still change it). #355
- Resuming a parked session after 1h repays cache write; accepted. shep-pm/shep#707
- Bot window grant serves one item, never inherited (would summon twice in a window the dog counted once). #103

## Issues

- The first prompt of a work item names the paths its issue names that `main` lacks as "may have moved", with the closest file that ends the same way. One `git ls-tree`, read in place and only when the body names a path. A folder on `main` resolves, and a name with no `/` counts only with an extension files on `main` have. `runner/turn/mod.rs`, #1322
- The issue check reads structure, not quality, but for one rule: a `Touches:` path a worker's fence refuses (`fence::owner`, the one list, from the path alone) fails as `Failure::Fenced`, so a ticket that needs a harness's file splits into a `ready-for-human` issue, which fails by design and gets no triager and no pick. `add_found` refuses it too (`AddError::Fenced`, a `Skip::Failed` on the board); `VERSION` 4 checks every open issue once more, the triage poll's listing alone, which skips a bot's issue unless it is the project's own App's and never lists a local ticket (`opened_by_us_or_people`, `Routed::open_issues`, triage-check.md, #1818). `board::check::check` over an issue's title, body and labels returns every part it lacks or holds malformed, each naming the part. The parts: a title; a `Touches:` line (any case, in a list or bold, as every labelled line is read) naming a path in backticks, on it or in the list under it, or a `Touches` heading with such paths under it; `What to build` with text under it and `Acceptance criteria` with a `- [ ]` item, as headings at any level and case, closing `#`s and bold dropped, a section ending at the next heading of its level or above; no `Acceptance criteria` item asking a worker to change another issue (`Failure::ChangesIssue`, read clause by clause); a line in a code fence (three or more backticks or tildes, closed by as many or more) is in no section and is no labelled line; a `Harness reach:` line with text when a `Touches:` path has a part after `adapters/` named for `claude`, `pi`, `codex` or `goose`; a `Blocked by:` line, when there is one, naming `#<n>` or `k<n>`; a `Needs:` line, when there is one, whose every entry reads `<registry>:<name>@<version>` with `crates`, `npm` or `pypi` as its registry (`Failure::Needs`); one priority label (`board::is_priority_label`, so a bare `P2` too); a kind, its one `kind:<type>` label, else its title's conventional prefix, being one of #1379's nine types (`board::check::kinds`: `guard::conventional_type`'s list less `build` and `revert`), two `kind:` labels refused and `bug`/`enhancement` not read. Sources: `CLAUDE.md`, `docs/agents/`. ADR 0018, `core/board/check.rs`
- `shep kelpie issue check <ticket>` reads the ticket through `ports.tickets` (`Routed`), prints that it passes or each failure, and exits 0 when it passes, 1 when it fails and 2 when it could not be checked. `check` as the first word after `issue`, wherever `-p` sits, is always the subcommand, and `verbs::main` runs it before asking for `SHEP_HOME`. `--draft <file> [--label <label>]...` checks a file, its first line the title, with no shepherd, settings or network, so it runs in a worker's sandbox, which reaches only the dog's door. `src/issues/check.rs`, `src/flock/verbs/check.rs`
- The issue skill (`skills.md`) holds the same format; its example passing the check, and its naming every part the check reads, are tested. `core/skills/issue/mod.rs`
- The board runs the check on each new or edited open issue, and the triager runs only on one that fails it: `triage-check.md`. ADR 0018
- A ready issue whose `Needs:` package is unpublished waits off the board as `Skip::Unpublished`. The check reads no network, so the triage poll asks `ports.registry` (`CurlRegistry`: crates.io index, npm, PyPI) with the lock let go, and `check_holds` reads the answers, holding a package unread. The board read asks too, for an issue the poll omits. A found package is kept, a miss is asked each poll, a failed read holds nothing, noted once. `runner/triage/unpublished.rs`
- `shep kelpie`'s help and its manifest's `verb` come from one table of top-level verbs (`src/flock/verbs/help.rs`): `USAGE` is rendered from it at build time, and `schema::verb` declares one subcommand per distinct verb name of the table and of `ELSEWHERE` (the verbs `main` runs itself; a test fails on a `command ==` arm of `src/main.rs` left undeclared), so shep's `--help` and completion cannot drift from the usage. Each `about` fits 60 columns. #1639
