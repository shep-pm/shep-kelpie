# Design: Catching a branch up with `main`

Part of the design index, `README.md`. CI and the merge are in `merge.md`.

- Branch behind `main` caught up by kelpie: rebase with lease, or merge where commits aren't kelpie's to rewrite. Conflict: kelpie starts `git merge --no-commit origin/main` in the worktree itself (so `main`'s files the sandbox refuses, `.claude/` included, land staged), and the worker turn only resolves the conflicted files, `git commit --no-edit`s and pushes without force. A rebase that conflicts falls back to that merge; a merge with no conflict is committed and pushed. `git.catch_up = "conflicts"` skips the catch-up for a head `git merge-tree` finds merging cleanly into `origin/<base>`: `Standing` (`runner/git_reads.rs`) answers `Base::Current` for it, so the gate, the review's catch-up and the merge's withdraw need no edit. A conflicting head, or one `merge-tree` cannot judge (git before 2.38 included), is caught up as under `always`, the default. The dependency rules read `base_of` and ignore the setting. A worktree already mid-merge is not merged again; unresolved parks `rebase`. It also runs from a review whose head has no checks once they settle, and returns there, not to CI, also on a yes to the `rebase` it parks. #61, #609, #1163, `runner/gate/catch_up.rs`
