# Agent board

The estimate the agent board picks an implementer or a reviewer by: when each agent would finish a work item, and what it would cost. ADR 0018. The estimate is pure, in `crates/core/src/agent_board/`. The dog runs it for a runner's `pick` ask (`crates/dog/src/dog/board/`), which dispatch makes for every new work item, and for a `fit` ask, which reads what every agent's record says about a kind.

- Typical time and cost (`History`, `typical.rs`): from the usage ledger's merged `finished` lines (metrics-work-items.md), the median `wall` of the first level that holds 5 items (`SAMPLES`): the agent's own items of the work item's kind, then every agent of its tier with that kind, then its tier with any kind. The cost is the median `cost_usd` of that level's priced lines, those with no `unpriced_calls` in either role, and unknown when none is. With no level, 1 hour (`DEFAULT_SECS`) and an unknown cost. An even count takes the mean of the middle two. A line's tier is its agent's tier as the caller reads it from the agent files, not the line's `tier`, which is what the item asked for; a line whose agent no file names counts toward no tier. A line or work item with no kind (a rework or an adopted item, or an issue with no `kind:` label) counts only toward the tier's any-kind level. Assumed chain: ADR 0018 names only the agent's kind and then its tier, so the tier's kind before its every kind, and the 1 hour default, are this file's reading. A reviewer's typical time and cost are that default, 1 hour and unknown: a finished line names the implementer that built the item and never a reviewer, and the dog's tier map holds implementers alone, so a reviewer's name reaching a line counts toward no tier (#1537).
- Typical turn (`History::turn_secs`): the same chain over each line's `wall` divided by its worker calls, since the line keeps no worker seconds, so a turn reads long by the review and CI time. A line with no worker calls gives no turn. With none, 1 hour, which is what a reviewer's turn reads as.
- Wait (`wait`, `wait.rs`): a gateway model's `ModelLoad` (`crates/core/src/ports/leased.rs`) has `held + waiting + 1 - slots` turns ahead when positive, served `slots` at a time, so the wait is `ceil(ahead / slots)` typical turns. A model that lists no slots has no turn limit and waits 0. An unread load has no window: the agent is not picked, never read as free. A plan account waits until its pacer `Hold`'s `until`, and with no hold waits 0. An `Unreadable` hold waits until kelpie looks again, its `until` `RECHECK_SECS` on. An agent with neither waits 0. A reviewer's wait reads exactly as an implementer's.
- Pick (`pick`, `pick.rs`): of the candidates, keep those whose file takes the item's kind (a file with no `kinds` takes every kind; an item with no kind goes only to such a file), whose tier is at least the item's, that are not left out, that have a window, and only the pinned one when the item has a pin. Finish is wait plus typical time. Those finishing within the item's slack of the soonest (its pick's minutes, else `agents.slack`, 60 when absent; the runner resolves it into the ask, and `DEFAULT_SLACK_MINUTES` only answers an ask that names none) come first, an agent with a cost before one with none, cheapest first, then soonest, then by agent name: an agent on a local model (`Candidate::local`, a limit not an account) with no priced history counts as $0, and an agent with no cost at all (a hosted agent with no priced history) follows them lowest tier first, `Fit::tier()` standing in for its price, so on a fresh install `sonnet-high` ranks before `opus-high`; the cost an answer reports stays its history's, or unknown, since the tier only ranks; the rest follow soonest first, so a handoff can take the next. Empty when none fits.
- The dog's board (`dog/board/`): the finished lines of every project, a folder of kelpie's home named as a project that holds `usage.jsonl`. It rereads a ledger on the availability tick (`LOAD_TICK`, 30s) only when its length or last write changed; one it cannot look at or read keeps its last lines, and only one that is gone leaves. An agent's tier is its file's, read at the dog's start. It ranks every implementer and reviewer file the dog knows (`Board::new`), and reads a ledger line's tier from the implementers alone.
- The `pick` ask (`PICK` on `lease.sock`, `PickAsk`; client `core/lease/door_pick.rs`): the item's kind, tier, pin, slack and leave-out, and the agents its project allows, which the runner resolves from `agents.allow`. The dog ranks the implementers and reviewers among them and answers `picks`, each `{agent, finish, wait, cost_usd}`; an empty list means none fits. A runner that cannot reach the dog gets no answer and starts nothing. Today only dispatch asks, and it names implementers alone: the `reviews.need` cut makes each review round ask for a reviewer (#1537).
- The dog's waits: a paddock model's last load, and one unread is not picked (its key: metrics-dog.md). A plan agent's is the pacer's window rule (`pacer::window`) on its last meter reading, or an `Unreadable` hold before the first. A model behind another gateway, or an agent with neither, waits 0. The dog has no day start or kickoff hours, so it reads no allowance: the runner's pacer still holds at dispatch.
- Track record (`Record`, `records`, `record.rs`; ADR 0018): per agent and kind, from every finished line (not only merged ones), keyed by the line's `agent` and `kind`; a line with no kind is under none, and a line with no agent counts toward no record. A record holds `items`, `merged`, `closed` (closed with no change), the median hours of merged items, `review_rounds`, `fix_turns`, `heavy_fix_items` (items with `HEAVY_FIX_TURNS`, 3, or more fix turns, each once), `rulings`, and the median cost of the merged items with every call priced. The merge rate is `merged` over the items not closed with no change, so a dropped item (not merged, not closed) counts against it and a closed one toward neither side; it is unknown when every item was closed. A record reaches a pick only through the typical time: `History` and `pick` do not read it. `fit` reads it for the `agent-fit` ruling, which moves no pick.
- Fit (`fit`, `fit.rs`; ADR 0018): of the agents whose file takes a kind (a file with no `kinds` takes every kind), every pair with `FIT_ITEMS` (10) items of it each where one does clearly worse: a merge rate `MERGE_RATE_GAP` (0.15) lower, median hours `HOURS_RATIO` (1.5) times or more, or a share of items with `HEAVY_FIX_TURNS` or more fix turns `HEAVY_FIX_GAP` (0.15) higher. A measure a record cannot say compares nothing, and a pair names the first measure that says it. A finding names both records, the measure, and the `kinds` the worse agent's file should name instead: its own without this kind, or every kind the records name without it when its file names none (empty when its file names only this kind). Nothing applies it.
- The `fit` ask (`FIT` on `lease.sock`, `FitAsk`; client `core/lease/door_pick.rs`): the agent and the kind. The dog answers `fits` as `yes` when the agent still fits the kind and `no` with the finding when it does not. It answers `no` for a pair only when the worse agent has `FIT_AGAIN` (10) more items of the kind than at the last answer naming it, and writes the mark before it answers, so one project of many raises a finding. The marks are the dog's own file, `<kelpie home>/dog/fit.json`, and survive a restart: one that cannot be read, that another build wrote, or that names an agent kelpie no longer knows marks nothing of that and says so on stderr. Nothing asks yet.
- `status` shows `records` beside `board` (`View::records`): agent, then kind (`none` for no kind), each with the fields above and `merge_rate`; null where unknown. It lists every agent a ledger names, implementer or not.
- `status` shows `board`: per implementer, `secs` and `cost_usd` for an item of no kind, and its `wait`; null when unknown. A reviewer is ranked and never shown.
