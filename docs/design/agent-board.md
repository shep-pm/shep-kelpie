# Agent board

The estimate the agent board picks an implementer by: when each agent would finish a work item, and what it would cost. ADR 0018. The estimate is pure, in `crates/core/src/agent_board/`. The dog runs it for a runner's `pick` ask (`crates/dog/src/dog/board/`), which dispatch makes for every new work item.

- Typical time and cost (`History`, `typical.rs`): from the usage ledger's merged `finished` lines (metrics-work-items.md), the median `wall` of the first level that holds 5 items (`SAMPLES`): the agent's own items of the work item's kind, then every agent of its tier with that kind, then its tier with any kind. The cost is the median `cost_usd` of that level's priced lines, those with no `unpriced_calls` in either role, and unknown when none is. With no level, 1 hour (`DEFAULT_SECS`) and an unknown cost. An even count takes the mean of the middle two. A line's tier is its agent's tier as the caller reads it from the agent files, not the line's `tier`, which is what the item asked for; a line whose agent no file names counts toward no tier. A line or work item with no kind (a rework or an adopted item, or an issue with no `kind:` label) counts only toward the tier's any-kind level. Assumed chain: ADR 0018 names only the agent's kind and then its tier, so the tier's kind before its every kind, and the 1 hour default, are this file's reading.
- Typical turn (`History::turn_secs`): the same chain over each line's `wall` divided by its worker calls, since the line keeps no worker seconds, so a turn reads long by the review and CI time. A line with no worker calls gives no turn. With none, 1 hour.
- Wait (`wait`, `wait.rs`): a gateway model's `ModelLoad` (`crates/core/src/ports/leased.rs`) has `held + waiting + 1 - slots` turns ahead when positive, served `slots` at a time, so the wait is `ceil(ahead / slots)` typical turns. A model that lists no slots has no turn limit and waits 0. An unread load has no window: the agent is not picked, never read as free. A plan account waits until its pacer `Hold`'s `until`, and with no hold waits 0. An `Unreadable` hold waits until kelpie looks again, its `until` `RECHECK_SECS` on. An agent with neither waits 0.
- Pick (`pick`, `pick.rs`): of the candidates, keep those whose file takes the item's kind (a file with no `kinds` takes every kind; an item with no kind goes only to such a file), whose tier is at least the item's, that are not left out, that have a window, and only the pinned one when the item has a pin. Finish is wait plus typical time. Those finishing within the item's slack of the soonest (its pick's minutes, else `agents.slack`, 60 when absent; the runner resolves it into the ask, and `DEFAULT_SLACK_MINUTES` only answers an ask that names none) come first, cheapest first, then soonest, then by agent name: an agent on a local model (`Candidate::local`, a limit not an account) with no priced history counts as $0, any other unknown cost goes last, and the cost an answer reports stays its history's; the rest follow soonest first, so a handoff can take the next. Empty when none fits.
- The dog's board (`dog/board/`): the finished lines of every project, a folder of kelpie's home named as a project that holds `usage.jsonl`. It rereads a ledger on the availability tick (`LOAD_TICK`, 30s) only when its length or last write changed; one it cannot look at or read keeps its last lines, and only one that is gone leaves. An agent's tier is its file's, read at the dog's start.
- The `pick` ask (`PICK` on `lease.sock`, `PickAsk`; client `core/lease/door_pick.rs`): the item's kind, tier, pin, slack and leave-out, and the agents its project allows, which the runner resolves from `agents.allow`. The dog ranks the implementers among them and answers `picks`, each `{agent, finish, wait, cost_usd}`; an empty list means none fits. A runner that cannot reach the dog gets no answer and starts nothing.
- The dog's waits: a paddock model's last load, and one unread is not picked. A plan agent's is the pacer's window rule (`pacer::window`) on its last meter reading, or an `Unreadable` hold before the first. A model behind another gateway, or an agent with neither, waits 0. The dog has no day start or kickoff hours, so it reads no allowance: the runner's pacer still holds at dispatch.
- `status` shows `board`: per implementer, `secs` and `cost_usd` for an item of no kind, and its `wait`; null when unknown.
- The runner's side (`runner/add.rs`, `runner/dispatch/`, port `ports::AgentBoard`, `DoorBoard` on `lease.sock`): a new work item from a ticket asks with the issue's `kind:` label, the project manager's tier and slack, the pin (the project manager's agent, else an `agent:<name>!` label's) and every implementer file `agents.allow` holds, by name, that the worker's fence and the gateways can run (`Runner::board_agents`); the answer is kept to those. Dispatch takes the first ranked agent `pace_agent` lets start, since the dog reads no day allowance; a usage read pending stops the walk. A plain `agent:` label chooses nothing. No answer starts nothing this poll and lists the issue `unpicked`; an empty ranking lists it `unpicked` naming kind, tier and pin; every ranked agent held lists it `paced`. Each waits for the next poll, with no fallback pick, and the next issue may start. `add` takes the first ranked, unpaced. Rework, adopted and contribution items take the first ranked too (`Runner::board_opening`), a pinned label or none, and are paced on it; no default implementer is left. The walk is `first_unpaced` (`runner/pace.rs`). The `FakeAgentBoard` ranks the ask's agents in order until a test sets one, or `ranks_finishing` sets each finish; the rig's puts `sonnet-high` first (`ranks_first`).
- Handoff (`runner/turn/handoff/`): before each due turn of an unpinned item, the runner asks with its kind, tier, slack, no pin and `leave_out` the agents it left (`WorkItem::left`). Its own agent ranked within the slack (its own, else `agents.slack`) of the soonest finish keeps the turn. Otherwise the first ranked agent `first_unpaced` lets start on the turn's scope takes it: a new session on the same branch, `Turn::Due`, its first prompt carrying `WorkItem::handoff`, kelpie's note of the branch's commits past the base (the newest 20, none before a worktree exists), the old agent's last `summary` (or that none is kept) and the prompt it was due. The note lasts until that turn ends, so a session that dies unborn starts over with it, and a second handoff before the new agent runs keeps it. An own agent a trusted pacer hold still holds asks nothing (`turn_still_held`). The slack rule is `within_slack`, which the dog's pick shares. The step log's `handed-off` line names `from`, `to` and both finishes; the board event says `handed off from <a> to <b>`; no label is written. No answer, an empty ranking, every ranked agent held, or an agent outside the ask's agents (no file, or `agents.allow` leaves it out, which fails its turn as agent-allow.md says) keeps the turn on its agent. State version 92.
