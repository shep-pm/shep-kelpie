# Agent board

The estimate the agent board picks an implementer or a reviewer by: when each agent would finish a work item, and what it would cost. ADR 0018, 0020. The estimate is pure, in `crates/core/src/agent_board/`. The dog reads and the asking side orders. It answers a runner's `pick` ask (`crates/dog/src/dog/board/`), which dispatch makes for every new work item, with what it read of each agent, and a `fit` ask, which reads what every agent's record says about a kind.

- Typical time and cost (`History`, `typical.rs`): from the usage ledger's merged `finished` lines (metrics-work-items.md), the median `wall` of the first level that holds 5 items (`SAMPLES`): the agent's own items of the work item's kind, then every agent of its tier with that kind, then its tier with any kind. The cost is the median `cost_usd` of that level's priced lines, those with no `unpriced_calls` in either role, and unknown when none is. With no level, 1 hour (`DEFAULT_SECS`) and an unknown cost. An even count takes the mean of the middle two. A line's tier is its agent's tier as the caller reads it from the agent files, not the line's `tier`, which is what the item asked for; a line whose agent no file names counts toward no tier. A line or work item with no kind (a rework or an adopted item, or an issue with no `kind:` label) counts only toward the tier's any-kind level. Assumed chain: ADR 0018 names only the agent's kind and then its tier, so the tier's kind before its every kind, and the 1 hour default, are this file's reading. A reviewer's typical time and cost are that default: a finished line names the implementer, never a reviewer, and the dog's tier map holds implementers alone, so a reviewer's name reaching a line counts toward no tier (#1537).
- Typical turn (`History::turn_secs`): the same chain over each line's `wall` divided by its worker calls, since the line keeps no worker seconds, so a turn reads long by the review and CI time. A line with no worker calls gives no turn, and with none 1 hour, which is what a reviewer's turn reads as.
- Wait (`wait`, `wait.rs`): a gateway model's `ModelLoad` (`crates/core/src/ports/leased.rs`) has `held + waiting + 1 - slots` turns ahead when positive, served `slots` at a time, so the wait is `ceil(ahead / slots)` typical turns. A model that lists no slots has no turn limit, waits 0 and is never full. Full (`full`) is `waiting >= slots`; no load read is never full. An unread load has no window: the agent is not picked. A plan account waits until its pacer `Hold`'s `until`, and with no hold waits 0. An `Unreadable` hold waits until kelpie looks again, its `until` `RECHECK_SECS` on. An agent with neither waits 0. A reviewer's wait reads exactly as an implementer's.
- Pick (`pick`, `pick.rs`): of the candidates, keep those whose file takes the item's kind (a file with no `kinds` takes every kind; an item with no kind goes only to such a file), whose tier is at least the item's, that are not left out, that have a window, and only the pinned one when the item has a pin. Finish is wait plus typical time. They come soonest finish first, then by agent name, and that is the dog's whole answer: no cost, tier or list orders it. Empty when none fits.
- Rank (`rank`, `pick.rs`): the asking side's order over the dog's picks, run by `door_pick::pick` for every pick: a new item, a rework, an adoption, a handoff and each review round. An agent is available (`available`) when it can start within the ask's slack (`starts_within_slack`: its pick's minutes, else `DEFAULT_SLACK_MINUTES`, 60) however late it finishes and its model's queue is not full (`Pick::full`), so a full local model is not available. Available agents come first, a held agent (below) after every one that can start, then an agent with a cost before one with none, cheapest first, then soonest finish, then by agent name: an agent on a local model (`Pick::local`: a model server or a gateway) with no priced history counts as $0, and an agent with no cost at all (a hosted agent with no priced history, a plan agent or an API agent, which waits 0 unless the API is held, when it waits the hold out and ranks behind agents that can start (agent-board-api.md)) follows them lowest tier first, `Pick::tier` standing in for its price; the cost an answer reports stays its history's, or unknown. The rest, which cannot start in time, follow soonest start first, then by name, so a project with one busy agent still opens its item and a handoff can take the next. Nothing branches on `agents.pm`: a project with no such file takes this rule on every item (ADR 0020).
- Budget (`Budget` in `core/lease/door.rs`, `budget` in `dog/board/pick.rs`): each pick names the budget its calls draw from: `Local` for an agent on a local model, `Plan` for one on an account window that bills no API key, `Credit` for one that bills the key (`bills_api`) while the month's spend (`View::credit`) is under `api.monthly_credit_usd`, and `Billed` for one that bills it with no credit set or the month's spend at or over it. Nothing new is configured: every class comes from what the dog holds, and a pick naming none, from an older dog, still reads. `startable` in `pick.rs`, run by `door_pick::pick` after `rank`, leaves out every `Billed` pick unless the ask pins an agent (agent-board-api.md). #1950.
- The maintainer's list (`[kelpie.agent_board] prefer`) is gone (ADR 0020): the dog reads nothing of it, `rank` has no listed step, and an older dog's `listed` on a `Pick` still reads, since `Pick` denies no unknown field. `settings migrate` strips the table from kelpie's own section (`src/flock/set/migrate.rs`), and `KelpieSettings::agent_board` is `Option<Gone>`, `deprecated` in the schema, so an old section loads and `doctor` says nothing.
- The dog's board (`dog/board/`): the finished lines of every project, a folder of kelpie's home named as a project that holds `usage.jsonl`. It rereads a ledger on the availability tick (`LOAD_TICK`, 30s) only when its length or last write changed; one it cannot look at or read keeps its last lines, and only one that is gone leaves. An agent's tier and kinds are its file's, and the dog's reread of the agents folder gives the board the new ones on its next pass (`Board::set_agents`, dog-settings.md). It ranks every implementer and reviewer file the dog knows (`Board::new`, `Board::set_agents`, one `ranked` build), and reads a ledger line's tier from the implementers alone.
- The `pick` ask (`PICK` on `lease.sock`, `PickAsk`; client `core/lease/door_pick.rs`): the item's kind, tier, pin, slack and leave-out, and the agents its project allows, which the runner resolves from `agents.allow`. The dog reads the implementers and reviewers among them and answers `picks`, each `{agent, finish, wait, cost_usd, tier, local, held, full, budget}`, the last five left off the line when unset; the runner ranks them (`rank`) and then drops what `startable` refuses. An empty list means none fits. An ask with `reading` (agent names) and no work item is a reading: the dog answers `picks` for each named agent it has a window for, whatever its kinds, read for an item of no kind as `status` reads it. A runner that cannot reach the dog gets no answer and starts nothing. Dispatch and handoff ask for implementers, and each review round asks for a reviewer (#1539).
- The dog's waits: a paddock model's last load, and one unread is not picked (its key: metrics-dog.md). A plan agent's is the pacer's spent rule (`pacer::spent`) on its last meter reading, the same rule the runner holds a turn at, or an `Unreadable` hold before the first. A model behind another gateway, or an agent with neither, waits 0. A plan whose meter shows no 5-hour window reads it as unstarted, so only its week can hold it.
- `status` shows `board`: per implementer, `secs` and `cost_usd` for an item of no kind, and its `wait`; null when unknown. A reviewer is ranked and never shown. `availability.api` (agent-board-api.md) is left out with no hold, else `kind` (`no_credit` or `spend_limit`), `until` and one `line`: "API: out of credit, checking again at 04:00 UTC" or "API: spend limit reached, back at 2026-12-01 00:00 UTC".
