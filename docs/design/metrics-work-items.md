# Metrics of work items

What kelpie's numbers say of its work items: how many are in each phase, how each ended, and what it took to finish. The rest of kelpie's numbers are in `metrics.md`. ADR 0012, #920.

## Series

- The ledger's `finished` line (`crates/core/src/usage/finished.rs`, budget.md) names the worker's `agent`, and the `harness` and `model` its file runs on at the end (none once kelpie no longer runs it), with `ci_fix_turns`, `ci_failures` (red heads by `runnable`, `sandbox_only`, `no_tests`, `timed_out`, as `kelpie_ci_failures_total`, kept in the work item's counts since state version 71) `held` (findings above a nit by `high`, `medium`), and `disputed` and `deferred` (findings the worker disputed or deferred, once per round sent, kept in the work item's counts since state version 75), so a work item's quality reads from one line. It names the work item's `kind` (its issue's one `kind:` label at `add`) and `tier` (the least the project manager's pick asked for), each left out when the work item has none (state version 91).
- `kelpie_work_items{phase}` gauge, sent after each step from the state file
- `kelpie_work_items_finished_total{outcome}`: `merged`, `closed`, `dropped`, from the ledger's `finished` line
- `kelpie_review_rounds_total`, `kelpie_fix_turns_total`, `kelpie_rulings_total`, from the same line
- `kelpie_findings_total{severity}`: `high`, `medium`, from the same line's `held`, the findings above a nit sent to the worker, each counted once across rounds (the work item's `held`)
- `kelpie_work_item_seconds_total{outcome}`, the wall time of finished items
- `kelpie_ci_failures_total{tests}`: each head of a work item's pull request the gate reads red, counted once per head, which the work item records, so a still-red yes at the same head counts it once. `tests` is `sandbox-only` when every failing test the logs name is in a module `docs/agents/sandbox-red-tests.md` lists whole, `runnable` when one is not, is in a module the doc lists only in part (a `some:` entry: kelpie cannot tell which of them), is a test failure in a runner kelpie cannot read (a failed step named for a test run with none of cargo's test or build shapes), or its names were cut off, or more runs failed than kelpie read, `none` when no test failed (lint, docs, fmt, or a build that never ran one, as a failed test build is). `timed-out` when a job's `timeout-minutes` ended a run kelpie read and no log names a failing test: a slow test and a run with no test named read apart. It needs every red run read (`omitted` 0); a log that names a failing test keeps its own class. The list is of this crate's modules, so it is used only on the repo that doc describes: elsewhere every failing test counts `runnable`. Each name is judged against its own cargo run, since one tail holds several. The names come from the logs a red run's prompt carries. A head whose logs kelpie could not read, or found none of, counts nothing; a queue removal is not counted. `runner/ci_failure/mod.rs`
