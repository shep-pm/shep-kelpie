# Agent board, the API hold

How the dog holds every API agent while the API refuses its key. The estimate and the dog's side are in `agent-board.md`. ADR 0018.

- The API hold (`api_refusal.rs`, `REFUSED` on `lease.sock`, `Ask::refused`, `AgentBoard::refused`; the dog's side `dog/availability/`): a runner that finds the API turned its key away for spent credit or a spent limit tells the dog, which holds every agent whose session harness `bills_api()` (every `login: api` agent shares one key) as a whole, implementers and reviewers alike, and answers `held` with the time. `wait` reads it through `agent_board::Availability::Plan`, so a held API agent waits until the hold ends, 0 with no hold, and ranks behind agents that can start: `Candidate::held` puts it after every unheld agent within the slack, before the list, cost and tier, so a short hold never lifts it ahead. A spent plan gets no such flag. A pinned item is not stopped by it, and a plan agent is not held. A second refusal keeps the later `until`, and a standing hold is not cleared before its time; the availability tick drops it once past. The hold lives in the dog's memory, as the forge hold does, so `shep restart kelpie` clears it after a top-up. `Refusal::hold_until`: a spend limit holds until the resume time it states when that is after now, else one `RECHECK_SECS`; exhausted credit, which states no time, and a spend limit whose time cannot be read hold `CREDIT_RECHECK_SECS`, 6 hours. Assumed, not recorded: the wording comes from Anthropic's documentation (a spend limit is "You have reached your specified API usage limits", resuming as "You will regain access on YYYY-MM-DD at HH:MM UTC"; credit is "credit balance is too low"), and the result text of a refused `claude -p` call is assumed to carry the API's message; a recording replaces the hand-written test fixtures on the first real hit. Nothing sends the refusal yet: the runner's side is a later issue.
