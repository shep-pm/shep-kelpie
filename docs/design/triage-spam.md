# Triage's spam check

The classifier an issue goes through after its limits and before its research call (#895): the settings, the port, what a hit does and what a failure does. The settings and pick rule are in `triage.md`, the pass itself in `triage-pass.md`, the author's round in `triage-author.md` and `triage-answers.md`.

- `[app.dogs.kelpie.triage.spam]`, an absent table meaning no check, with `deny_unknown_fields`. `crates/core/src/settings/triage.rs`
  - `gateway`: a gateway named in kelpie's own `[gateways.<name>]`. Absent means no check at all. `Gateways::check_triage_spam` refuses a start, a `reread` and a `shep kelpie set` whose gateway kelpie's settings lack or cannot dial, naming `triage.spam.gateway`. A gateway whose key is unset is not refused there either: kelpie cannot ask it, so the check is off for the run and told once, and the runner starts. `crates/core/src/settings/gateway.rs`, `crates/runner/src/runner/mod.rs`, `runner/reread/`, `src/flock/set/mod.rs`
  - `path`: the route its classifier is served on, such as `/classify`. `ClassifierPath` refuses one that is not a single path: it needs a leading `/` and holds no control character, no space and no `#`, each of which would put a line of its own in the request. `Triage::check` refuses `gateway` with no `path`, naming `triage.spam.path`.
  - `threshold`: default 0.8. `Probability` is a `#[serde(try_from = "f64")]` newtype held in millionths and read down to the millionth at or below the number it stands for, so it is `Eq` and comparable, a threshold is met by an exact comparison and not a float one, and an answer is never raised to a threshold it was under: held to the thousandths, 0.7996 would stand at 0.8 and be read as spam at the default threshold. A threshold written with more than six decimals is read down the same way. A value outside 0 to 1 is refused naming `triage.spam.threshold`. It is written back as the number it stands for. `crates/core/src/ports/classifier.rs`
- The question is the one yes/no question `spam`: "Is this issue spam, an advertisement, or text unrelated to the project?" The request is the gateway's classifier shape: a `state` of the issue's title, its body cut as `max_body_kb` cuts it for the call, `author_association` and the account's age in days, the last two `null` when the forge cannot say, and `questions` holding that one question. The answer is the probability it is spam, read from `answers` under the question's name or from the name at the top level; a number outside 0 to 1 is no answer. `crates/adapters/src/adapters/classifier.rs`
- It is a port, `Classifier`, so a test answers it in memory (`crates/core/src/test/classifier.rs`) and no triage test reaches a gateway. The gateway's address and key come from `Gateways::upstream`, the same `Upstream` every other gateway call is made with, and the request goes through `paddock::send`. `crates/core/src/ports/classifier.rs`
- It is asked after the four limits, so an issue a limit held costs no classifier call, and the maintainer's own issues and one `shep kelpie triage` asked for skip it, on the same flag that skips the limits. `runner/triage/`, `runner/triage/spam.rs`
- At or above `threshold` the issue gets `possible-spam`, made on a repo that lacks it, and nothing else: no comment, no research call, no close, no lock and no hide. Kelpie never decides that an issue is spam on the maintainer's behalf; the label is the ask. Its record is `done` with `spam` the probability (state version 70) and no call of its own, so the check spends no place of `per_day` or `per_author_per_day`, and `status` says it. The calls the issue made before it join the record, its own record's and the ones saved against it while it had none (`TriageState::take_calls`), since a saved call stops being counted once the issue has a record, and a research call that came to nothing keeps its place either way. `possible-spam` joins `TRIAGE_LABELS`, so the pick rule leaves it alone, and `triage_ask` lets the verb through the label: the verb is how the maintainer overrules the check, and it takes the label off when the issue's record says kelpie read it as spam. A `possible-spam` no record of kelpie's says it put on came by hand, and stands as any hand label does. `crates/core/src/state/triage.rs`, `runner/triage/`, `src/flock/control/plain.rs`
- The label goes on before the record is saved. A save that fails takes the label off again and the error goes on to `triage_failed`, so the issue is untouched and the next poll asks the classifier a second time, since `untouched` skips a labelled issue and the verb takes `possible-spam` off only for a record that says spam. A label that cannot be taken off is told in a note naming the issue and both errors. `runner/triage/spam.rs`
- Below the threshold the pass goes on as it was.
- A gateway that cannot be reached, that refuses, or whose key kelpie's environment does not hold, is told once and turns the check off for the rest of the run, so an outage costs one attempt and not one timeout per issue; the next start asks again. An answer kelpie cannot read is no outage: the gateway is there and answered, so it is told once and the check is asked again for the next issue, which keeps one malformed reply from switching the check off for every later one. The pass goes on without the answer and the limits still hold, so an outage opens no flood. `runner/triage/spam.rs`
- Each check that got an answer is a ledger line of its own: role `triager`, kind `spam-check`, the issue it asked about, no tokens, no cost, no session and no harness. It is no `triage` line, so it moves no role total in `usage` and spends no place of a cap. It names its issue the way the triager's research line does (`runner/flight/triage.rs`), so `shep kelpie usage` lists it under that issue beside the calls of an issue kelpie never took on, which is what the report already does for every triaged issue. A check that got no answer is not on the ledger. `crates/core/src/usage/mod.rs`
- It is no model call in kelpie's counting: no session, no harness, no lease, no slot, no work item record, and no call the caps count.
