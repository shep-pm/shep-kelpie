# Agent file migration

How a file that predates the binding keys gets them. The agent file and its baselines are in agent-files.md.

- A stub of a file kelpie stopped shipping (#1287: `sonnet-high` `opus-high` `defect-hunter-lite` `iq3-xxs-review` `qwen`, their text kept in `REMOVED` in `legacy.rs`) is rewritten by `migrate` into the whole file, once: a bare `extends` stub becomes the shipped text, and a stub with keys of its own becomes the merge of its keys over that text, so the agent still loads and the project keeps running. `pending` lists it, and the line reads `wrote the whole of kelpie:<name>`.
- Settings (#1287): `settings migrate` (`src/flock/set/migrate.rs`, `DEFAULTS` and `DEFAULT_REVIEWERS`) writes the four names the code no longer defaults, `agents.representative` `triage.agent` `contributions.security_reviewer` and `contributions.reviewers` (`iq3-xxs-review` first where kelpie's section holds a `paddock` gateway, then `defect-hunter-lite`), into each project's table that leaves one unset, so a project that relied on them runs as before. The reviewers come after the step that carries a project's old reviewer list, a key already set is kept, and a project still unset after it is refused where the agent is needed. Run by `upgrade` with the other settings steps.
- Migration (#1284): the baselines carry no binding, so `legacy::migrate(folder)` (`crates/core/src/agents/legacy.rs`) writes into each file whose own text has `extends: kelpie:<one of the seven>` the binding that baseline shipped with before #1282: each of `harness` `model` `effort` (and `second_look` for defect-hunter) the file does not set, after its `extends` line, with comments, other keys and body kept. A file that sets a `harness` other than the baseline's (`claude-code`) but lacks `model` or `effort` is skipped and named (the old model ran on Claude Code). One on `command`, `endpoint` or `bot` is left alone: those take keys of their own. A file extending `kelpie:advisor`, `kelpie:researcher` or `kelpie:issue-writer` (ADR 0018) is deleted if it holds only `extends` and binding keys, else named, with what its role went with; the loader refuses the three roles. A symlink is written through and stays a link. Written by temp file and rename; a second run writes nothing; a chain needs nothing, since a file extending a stub inherits its keys. Run by `agents migrate`, by `upgrade` after the install, before the restarts (bare: in process; `--ref` `--release` `--binary`: `<installed> upgrade migrate`, agents then settings; `--rollback`: none; a failed agent step said; refused settings stop before any restart; older builds: `docs/guide/upgrading.md`), and by the dog's start next to `refresh_baselines`, since the upgrade that first brings the step runs on a build without it. `doctor` names `shep kelpie upgrade` or `shep kelpie agents migrate` for a stub the step would write (`legacy::pending`, which sees the folder even when the book is the embedded one), and the reason for a skipped file, which the loader leaves out of the book (`Agents::broken`) and `unbound()` does not list. The table is read only there; slice 5 (#1232) reads it again to inline the stubs of the files it drops.
