# Agents

Harnesses and gateways, and the agent settings. The agent file itself is in agent-files.md. The runner loop is in workers.md, the fence in fence.md, skills in skills.md, repo plugins in plugins.md, waits and spend by role in waits-and-spend.md, `agents.allow` in agent-allow.md.

- `pm`, `representative` (default `representative`, checked only when `contributions.pick` is not `off`, representative.md), `slack` (minutes, 60, agent-board.md); missing or wrong-role file stops runner. Implementers: every `role: implementer` file `agents.allow` holds, by name (`Settings::allowed_implementers`); one the fence or gateways cannot run is left off the board's ask (`Runner::board_agents`). Reviewers: no setting here; their candidates are in agent-allow.md. ADR 0018, #1544, `crates/core/src/settings/agents/mod.rs`
- A new CLI is a folder `adapters/<cli>/` with an `impl Cli` (required: `write_config`, `command`, `policy`, `parse`, `parse_adopted`; the rest default), a `HarnessFacts` row in `core/settings/agents/facts.rs`, and one entry in `Routed::new` (`src/sheep/mod.rs`). `CliAdapter` does the rest. cli-adapter.md
- `HarnessFacts` declares `edits`, `resumable_session`, `repo_reads` and `role_guard` for every harness, including the stand-in. All four harnesses edit, resume and read; only Claude Code's adapter wires kelpie's PM guard (`role-guard`). `Harness::serves(role)` checks the role's needs; `serving(role)` filters `ALL`. No adapter changes. ADR 0006, #1285
- Harness parity: pi gets every capability Claude Code has, in the same PR or an open issue; Codex follows pi, blocked by its issue (maintainer, 2026-10-13: pi is in everyday use, Codex is not). A refusing default is a tracked gap. #752, #753, `CODING_STANDARDS.md`
- Every agent call (Claude Code, pi, Codex, goose) writes stdout and stderr to files beside its settings, not pipes: a pipe the sandbox's Node made non-blocking killed Codex on large output, and files outlive the runner's memory. A record (`<settings>.call.json`: pid, process group, role, issue, output paths, `Ending` asked, the runner's `Flying` ceiling and turn flags) sits beside them from spawn to the call's end by any means, a stop included. A handover reads it. `crates/adapters/src/adapters/process/record.rs`, #716
- Every harness runs its call with `TMPDIR` at the call's own scratch folder (`<settings>.tmp`), which its sandbox may write and which is emptied before each call; Claude Code, pi and Codex also set `TMPPREFIX`, which zsh uses for a heredoc instead of `TMPDIR`. The worker's instructions send its scratch files there, since `/tmp` is refused and every worker shares it (`docs/adr/README.md`): a worker that wrote there lost a turn finding out. #951, `crates/core/src/worker-instructions.md`, `crates/adapters/src/adapters/claude/sandbox.rs`, `crates/adapters/src/adapters/pi/mod.rs`
- pi: second harness; kelpie extension runs `confine` + `guard`; forwarder passes only chat completions. No Claude Code hooks, so beside `worker.guard_hooks` a pi or Codex implementer is left off the ask, its turn fails. #130, #235, `crates/core/src/settings/agents/mod.rs`
- pi runs each call with `PI_OFFLINE=1` in its environment, so pi never tries to download the `rg` and `fd` its own `grep` and `find` run, which the sandbox refuses. `--offline` is in the arguments too, and pi maps it to the same variable; the environment is what pi's tools read and reaches every program pi starts. #972, `crates/adapters/src/adapters/pi/mod.rs`
- A project with an agent on pi gets a `pi tools` doctor line for `rg` and `fd`, which pi's own `grep` and `find` run: pi looks in the call's own pi home's `bin` folder first, which is always empty, then on the `PATH`, then downloads them from GitHub, which the sandbox refuses. Each line names the program the `PATH` actually has, since pi takes `fd` under either name. #972, `src/doctor/machine.rs`
- Codex: third harness (ChatGPT plan windows beside Claude's, each paced on own); session ids map to Codex threads. Own login in `codex_home`, fresh `CODEX_HOME` per call (`~/.codex` copied maintainer's history). #233, `crates/adapters/src/adapters/codex/mod.rs`
- goose: fourth harness, a model on an OpenAI-compatible server; worker (in the fence, by a `PreToolUse` plugin), reviewer and retro (same plugin, `guard --goose=<build> --read-only`: `shell` runs only the Codex read-only list, `tree` allowed, `write`, `edit` and any other tool refused as a call that writes no file, except that a reviewer asked for tests (#795) has `--goose-write=<folder>` after `--read-only` and its `write` goes to `kelpie confine <folder> <folder>`; a retro loses the sandbox's `write`; a call with no fence has no extension and `GOOSE_MODE=chat`; a resumed reader takes no extension flags, so the hook is its only gate). A goose reviewer gets a fence with an empty folder of its own, as Codex's does. #789. goose cannot run an `after_command` hook: its `PostToolUse` has no result. A worker turn crosses a handover (handover.md), and a handover waits while a goose worker is attached (`attach` resumes it with `goose session --resume` in `GOOSE_MODE=approve`, and its forwarder lives in the running image's memory, as pi's does). `docs/facts/goose-as-an-agent.md`. #784, #788, #791, #796, `crates/adapters/src/adapters/goose/mod.rs`
- goose's watch (`shep kelpie watch`) reads the call's stdout file, since its sessions are in SQLite under `GOOSE_PATH_ROOT`: `GooseCli::transcript` logs the call's goose root as the `session-started` step's folder (the log's shape is unchanged), and the locator reads the root's sibling `<stem>.stdout.jsonl`. The file is emptied by each call, so goose's `HarnessFacts::transcript` is `None`: no file holds a whole session. An `error` event has no time, so the watch gives it the time of the line before it. #790, `crates/core/src/watch/goose.rs`, `crates/core/src/watch/locate.rs`
- Codex writes only an allow-list of its home (`.env`, `AGENTS.override.md` could disable guards). Shell: worker `guard`, others `guard --read-only`, none unfenced. `crates/core/src/guard/reading/mod.rs`
- `e2e.host` ssh alias, must be disposable (workers edit the script); worker asks only `take: "e2e"`; dog runs one per host under 30 min. #415, #521, `dog/e2e/`
- Gateway (`kind`, `url`, `key_env`) is reached through the `ModelGateway` port (`crates/core/src/ports/gateway.rs`: models, key check, optional lease), one adapter per `kind`, `paddock` (the default) and `openai` (any OpenAI-compatible gateway: models and key from `GET /v1/models`, no lease, so it may evict a model a turn runs on); a kind with no lease runs its turn at once, ceiling from its start. It queues and places models: agents unpaced, lockless; key unset in every call + child; every call (worker turn, reviewer session or round) holds a heartbeat lease, and a `turn` reason is the wait (`gpu_wait`, `waiting`); a lease paddock refuses to renew, or leaves unanswered past its ttl, fails the turn, and a drop releases at once; every chat call to a keyed gateway sends `x-paddock-priority: batch`; a worker's pi chat calls and an endpoint round's also send `x-paddock-lease: <id>`, their own lease (a reviewer's session names none), and a round sends `x-paddock-max-wait: 1800s` too, taken before its forwarder opens. The key is read only where the runner holds it, at its start and reread, and in `doctor`; `shep kelpie set` checks a gateway's shape (named, its URL dialable) and no key, since the maintainer's shell has none. #352, #497, #500, #606, #607, #712, #965, `crates/process/src/spawn.rs`
- A call queued for its gateway lease is never read as idle or stuck, for a worker turn or a reviewer round alike: its quiet counts from the grant (`Watched::granted`), and a wait past 10 min is its own wake, naming the holder read from the gateway's `GET /paddock/status` once per wait episode. A wait that was never for a lease, because its gateway answered busy or its host could not be reached, is named by what it waits for, on the board and in the wake alike, and no holder is read for it. #964, `runner/briefing/`, `runner/pm/`
