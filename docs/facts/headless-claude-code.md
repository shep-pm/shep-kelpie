# Headless Claude Code

Measured 2026-09-24 on Claude Code 2.1.282, `--model sonnet`, one sample each. Floor means input plus cache write plus cache read on a trivial prompt.

- Baseline floor 41,012. `--setting-sources ""` gives 22,927, and also drops hooks and plugins. `--strict-mcp-config` with an empty `--mcp-config` gives 36,935. `--disable-slash-commands` gives 36,482. All three together give 26,273. `--tools ""` grows the floor to 91,744.
- `--bare` refuses subscription login. It reads only an API key.
- Two identical fresh calls share the whole prefix: the second reads 41,010 from cache. A different working directory shares only about 10k.
- The first `--resume` onto a fresh session rewrote about 29k of cache in one early probe. Seven runs in the transport series wrote only the new turn (about 5.3k), so it did not reproduce.
- `total_cost_usd` is cumulative across a resumed session. `usage` is per call. Measured again 2026-09-26 on 2.1.283: `modelUsage` is cumulative too, and the top-level `usage` sums every request inside one call. The recorded pair is in `fixtures/`.
- A call killed within its first second leaves no transcript. `--resume` onto it prints "No conversation found with session ID" and exits 1 with no JSON, and `--session-id` can take the same id again. Once a transcript exists, `--session-id` refuses the id as already in use.
- Where the config folder lives, measured 2026-10-27 (#1421). A worker's `--resume` failed with "No conversation found with session ID" while the session's transcript sat in `~/.claude/projects/<slug>/<id>.jsonl`, written minutes before, and the `--session-id` call that started over accepted the same id, which it refuses once a transcript exists. Worker sessions restarted within 2 minutes were 11% of Claude Code starts before #1259 and 19% after it. The folder the fence carved back matched the one Claude Code wrote, so the cause sat in the `~/.claude` deny and carve-out. Kelpie now sets `CLAUDE_CONFIG_DIR` to `claude/<ticket>/<role>/` under the project's kelpie home, which holds the transcripts at `projects/<slug>`. With `CLAUDE_CONFIG_DIR` at an empty folder and no `CLAUDE_CODE_OAUTH_TOKEN`, `claude -p` wrote its transcript there and answered "Not logged in", since the keychain login is kept per config folder, so a call with no token fails with `LOGIN_FIX`. Kelpie logs a `resume-lost` step in `steps.jsonl` when a resume finds no session, with the harness, the session and whether its transcript file was there.
- `/compact` works under `-p`. The result carries `local_command: "compact"` and `num_turns: 0`. Context went from 125,122 to 54,484 on the next turn, which wrote a fresh 42.6k cache. `/compact <instructions>` is accepted.
- A repo's plugin does not reach a kelpie worker, measured in shep-pm/shep-kelpie#569: a headless `claude -p` in a kelpie worktree lists no `rust-house-style:rust-house-style`, and with `--plugin-dir` at the plugin's folder it lists it. 46 of 73 worker retros reported "Unknown skill: rust-house-style". Slice 1 (#570) is tested against stand-ins. Live on this repo on 2026-10-12, after #570 and #608: the first runner start fetched the marketplace copy, and a worker's next turn listed both `rust-house-style:rust-house-style` and `tui-screen-capture:tui-screen-capture`.
- Plugin skills under `-p`, measured 2026-09-29 on Claude Code 2.1.285 with Haiku 4.5, one sample each:
  - A `--plugin-dir` plugin loads under `--setting-sources project`, and `-p "/<plugin>:<skill> <args>"` runs the skill even with `disable-model-invocation: true`, on a fresh session and on `--resume` alike. Multi-line arguments reach it whole.
  - An unknown skill, or a `--plugin-dir` that doesn't exist, is no error: the call succeeds and the model answers that the command "isn't available".
  - A plugin manifest's `skills` list does not load an absolute path outside the plugin's folder. A copied skill answers to both its folder's name and its `SKILL.md` name.
- Trimming unused features, measured 2026-10-01 on Claude Code 2.1.286 with Sonnet, floor as above, two samples each, identical. A reviewer's settings file (`deny` of `Agent`, `Task` and `Bash`) gives 16,093. The same file with `disableBundledSkills`, `disableWorkflows`, `disableClaudeAiConnectors` and `disableArtifact` set, and the plan-mode, cron, design and worktree tools added to `deny`, gives 9,011: 7,082 fewer on every turn. A bare tool name in `deny` removes the tool's definition, where a scoped rule only blocks the call.
- Context floor with an allow-list, measured 2026-10-10 on Sonnet 5.5 with a trivial prompt in an empty repo, `--setting-sources project` as a worker runs, counting input plus cache write plus cache read:
  - As a worker ran: 18,385.
  - The five `disable*` settings (`disableBundledSkills`, `disableWorkflows`, `disableRemoteControl`, `disableClaudeAiConnectors`, `disableArtifact`): 12,240.
  - `--tools Bash,Read,Edit,Write,Glob,Grep,Skill --strict-mcp-config`: 10,521.
  - Both: 8,265.
  - `--tools Bash,Read,Edit,Write,Glob,Grep --strict-mcp-config`: 7,478.
  - The list had also carried the account's claude.ai connectors, `Agent`, `Workflow`, `ScheduleWakeup` and the deferred tools, none of which a worker can use. At about 10k a turn, a worker of 270 turns re-read about 2.7M tokens it never needed.
  - Kelpie now starts a worker with the third row's tools (`Bash,Read,Edit,Write,Glob,Grep,Skill` with `--strict-mcp-config`) and a reviewer with `Read,Glob,Grep`.
- Issue writer's floor with an allow-list, measured by the maintainer 2026-10-19 on Claude Code 2.1.303 with `claude-opus-5-5` at medium effort as the issue writer runs, trivial prompt in an empty git repo, `--setting-sources project`, a settings file holding the issue writer's bare-name denies and `disable*` switches, counting input plus cache write plus cache read, two samples each, identical: no `--tools` 8,113, `--tools Bash,Read,Glob,Grep,Skill` 7,812. The allow-list saves 301 tokens here, because a bare name in `deny` already removes a tool's definition. Most of the 13.2k an issue writer starts at in real calls (the maintainer's median of 6 session first requests over the 7 days before #985) comes from what an empty repo leaves out, its `CLAUDE.md`, skills, plugins and MCP servers, rather than from the built-in tool list.
- What dropping the code graph takes off a worker's request, measured 2026-10-19 (#991). `claude -p` is refused for a worker (the guard stops a worker starting an agent of its own, and the sandbox reaches no model host), so the floor was not re-measured before and after. The removed definitions were read instead from the `api-request-shape` line of real worker sessions on Claude Code 2.1.302 and 2.1.303: the code graph's 17 tools are 16,470 bytes of JSON in the request's `tools` array, which is 28,926 bytes for a worker given the graph and 12,456 without it. At the 4,300 tokens measured for the same 17 tools as 17,122 characters on pi, that is about 4,100 tokens off every request of a worker's turn. `mcp-servers.md` has the sessions, the counts and the per-tool sizes.
- Worker instructions bytes, measured 2026-10-19 in the rig (#992). `claude -p` is refused for a worker (kelpie's guard stops a worker starting an agent of its own, and the sandbox reaches no model host), so the token floor was not re-measured; the bytes are, and Claude Code carries them on a session's first call and every later request:
  - The instructions file a worker's first turn starts with, on a rig whose repo takes its owner's 2 KiB `.github` template: 11,448 before, 8,171 after the template moved to `pull-request-template.md` in the item's build folder, the deferred and disputed findings rules moved to the header of the findings file, and two worked question examples left.
  - The same rig with no owner template: 9,223 before, 7,899 after.
  - `crates/core/src/worker-instructions.md` itself: 7,763 before, 6,653 after.
  - A shep-kelpie item's file measured 10,823 on 2026-10-14, of which the owner's template was 1,924 and the headless rules 661.
- Worker's skill listing, measured 2026-10-19 (#993). `claude -p` cannot run in a worker's sandbox: the guard refuses a worker starting an agent of its own, and the sandbox reaches no model host. So the floor was not re-measured here, and the listing is counted from the plugin folders a worker call is given, by the entry Claude Code carries, `- <plugin>:<name>: <description>` and its newline.
  - Before: the worker's `--plugin-dir` flags named `mattpocock`, holding all 15 vendored skills, and `kelpie-wording`. 8 of the 15 are listed, 7 carrying `disable-model-invocation: true`. The maintainer's count of 88 worker listings in the transcripts since 2026-10-14, each holding 11 or 12 entries, is 12 entries and 3,076 bytes.
  - After: the folder holds `implement`, `tdd`, `diagnosing-bugs`, `pr`, `code-review` and `codebase-design`, so 5 vendored skills are listed (`implement` is written and not listed) and the listing is 9 entries and 2,581 bytes. `domain-modeling` (182 bytes), `grilling` (176) and `writing-for-agents` (137) are gone: 495 bytes, about 125 tokens, off every request.
  - pi lists the same skills with their file paths: 10 entries in 4,705 characters before, of which those three are 1,004, about 250 tokens on a 65k context. Counted from the folders the same way, not from a run.
- Two concurrent `--resume` calls on one session both succeed and run one after the other. `--fork-session` gives a new session id and a separate transcript.
- Flags missing from `--help` but present in the binary: `--max-budget-usd`, `--task-budget`, `--autocompact`, `--session-id`, `--resume-session-at`, `--channels`, `--dangerously-load-development-channels`.
- The CLI parses rate-limit data into `five_hour` and `seven_day` windows (plus `seven_day_opus` and `seven_day_sonnet`), each with a utilization and a reset time. `-p --output-format json` does not carry it, stream-json does as `rate_limit_event`, and headless `claude -p "/usage"` reads it for free.
- What the API says when it refuses a key, doc-cited as #1667 gives it, not measured: no real refusal has been seen and the pages were not read again for #1668. A spend limit the organization set is HTTP 400, `invalid_request_error`, starting "You have reached your specified API usage limits" (or "specified workspace API usage limits") and stating when access resumes. The same page's 429 `rate_limit_error` sample, with no `retry-after`, ends "You will regain access on 2026-09-01 at 00:00 UTC", the only dated wording the docs give (https://platform.claude.com/docs/en/api/rate-limits). Exhausted credit is "Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits.", with no reset time, and Claude Code shows "Credit balance too low" with a billing link (https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers). The docs leave unsaid how `claude -p --output-format json` carries any of these, whether its result text holds the API's message, and what a pi API agent's failure detail holds. `api_refusal::refusal` and the runner's `turn/refused/mod.rs` read the text of an `AgentError::Failed` on that assumption. The tests' fixtures are hand-written from the doc text, and a recording replaces them on the first real hit.
