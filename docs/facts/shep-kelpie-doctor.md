# `shep kelpie doctor`

- Doctor reuses runner ports for shared dependencies and its own `Host` port for machine checks.
  - Shared ports include `Meter` for `claude` (`/usage` answers only for a logged-in account, and a `claude` that cannot start is a spawn error), `Forge::viewer` for `gh`, `Reviewer::check` for the local round, `Alerts` for the test alert, and the shepherd connection with its minor check.
  - Two `Forge` questions are new: `can_push` and `review_bot_seen` (shep-pm/shep-kelpie#112). `Host` is doctor's own port for sandbox programs, pi/goose versions, executable lookup and Linux browser libraries.
  - `GithubApp`, which the runner takes up with #397, answers the App's line: its token for a project's repo says whether kelpie's App covers it (shep-pm/shep-kelpie#396).
- Doctor checks `pi` for each project with an agent on pi: `pi --version` prints a bare version such as `0.85.1`, and a pi at `PI_MINIMUM` (`crates/adapters/src/adapters/pi/mod.rs`, 1.0.4) or later is `ok`. Built-in MCP needs 0.99 or later, and compaction events carry a `reason` from 1.0.4. A pi off the `PATH` or older than the minimum is `MISSING`, and one whose `--version` fails, takes over 10 seconds or prints something that is not three numbers is `unsure` and never fails the run. The runner does not check the version at start. Read from pi's release notes, not run against a pi 1.0.4 (shep-pm/shep-kelpie#759).
- Doctor checks `goose` the same way for each project with an agent on goose: `goose --version` prints its version with a leading space, ` 1.54.0`, which the shared reader trims, and a goose at `GOOSE_MINIMUM` (`crates/adapters/src/adapters/goose/mod.rs`, 1.53.0) or later is `ok`. `on_failure: block` hooks need 1.48 or later, and 1.53.0 is the source the adapter is written from. A goose off the `PATH` (fix `brew install block-goose-cli`) or older than the minimum (fix `brew upgrade block-goose-cli`) is `MISSING`, and one whose `--version` fails, takes over 10 seconds or prints something that is not three numbers is `unsure` and never fails the run. The runner does not check the version at start. Not run against a goose 1.53.0 (shep-pm/shep-kelpie#786).
- Doctor gives each project with an agent on pi a `pi tools` line for `rg` and `fd`, which pi's own `grep` and `find` tools run. pi looks for each in its own agent folder's `bin` first, then on `PATH` (`fd` under either name `fd` or `fdfind`), then downloads it from GitHub (`dist/utils/tools-manager.js`, pi 1.1.0). Every kelpie pi call has a pi home of its own, so its `bin` is always empty, and the sandbox refuses the download. Either one off the `PATH` is `MISSING`, naming the tool it breaks and every name pi accepts for the program (fix `brew install ripgrep fd` on macOS, `apt-get install ripgrep fd-find` on Debian). The `ok` line names the program the `PATH` has, and says when it is an alias, as `fdfind` is for `fd`. Measured 2026-10-16 on the maintainer's machine, where neither was on the `PATH` at the time and pi's `grep` failed 22 times in three days (`docs/facts/tool-errors.md`, #972).
- `gh repo view <repo> --json viewerPermission` answers `ADMIN` on this repo for the maintainer and `READ` on `cli/cli`. `ADMIN`, `MAINTAIN` and `WRITE` push. `gh search prs --repo <repo> --commenter app/coderabbitai --limit 1 --json number` answers `[{"number":649}]` on shep-pm/shep and `[]` on `cli/cli`. Recorded in `crates/adapters/src/adapters/gh/access.rs`.
- GitHub gives no way to ask whether an app is installed on a repo without the app's own credentials, so CodeRabbit "installed" means it has commented on a pull request there. A repo it has not reviewed yet reads the same as one without it, so that line is `unsure` and never fails the run. A repo GitHub marks private that lists CodeRabbit is `MISSING`, which is what the runner refuses at start.
- The sandbox needs `sandbox-exec` on macOS (`/usr/bin/sandbox-exec` is there on the maintainer's machine) and, on Linux, `bwrap` alone: from shep-pm/shep-kelpie#1199 the Linux sandbox is crabpot in kelpie's own binary, whose proxy is Rust, so no `socat` is needed and no node `srt` is checked there. `bwrap` is from Claude Code's documentation, and the `sandbox` CI job runs the pinned escape tests under it.
- On Windows the `sandbox` line reads the crabpot install through `crabpot::windows_status` and names each state that stops a worker: no install or another setup version (fix `crabpot windows-install`, with `--allow-loopback` only when a project this run covers has `browser.enabled` and its base branch has a `.claude/launch.json` with a configuration, which is what plans a dev server that binds a local port; asked about one project, other projects do not count, and a line on what opening loopback allows), the Secondary Logon service off, session 0, a runner the sandbox user cannot read (MISSING, with the exe's own path in the line and `icacls "<path>" /reset` as the fix, and a `cargo install` from `%TEMP%` named as the usual cause), and the fence's loopback mode; an unreadable install is MISSING too. A listening policy on a closed install is MISSING, since the wrap refuses it. The runner check is crabpot's own, carried by `WindowsStatus::runner_readable` (crabpot#259), and `None` from it is no gap, since crabpot's start refuses nothing on it. The states before it were read from crabpot 0.2.0's source (shep-pm/shep-kelpie#1217); the runner one was found on the crabpot Windows VM (shep-pm/shep-kelpie#1530, `docs/facts/worker-profile-and-sandbox.md`).
- Measured 2026-09-29 with this branch's build on a scratch shepherd (shep 0.11.0) and a scratch kelpie home, on a clone of shep-pm/kelpie-scratch:
  - `add` then `doctor` printed `ok` for `claude`, `gh`, the sandbox, the shepherd, push access, the three labels, CodeRabbit and the local command, and `MISSING` for rulings, since that shepherd had no `webhook` table. It exited 1 and the flock was as `add` left it.
  - With no shepherd running it printed the missing shepherd and skipped the projects. `--test-alert` with no webhook posted nothing.

- Linux library checks (#194): `ldd` prints `libselinuy.so.1 => not found` for a copy of `ls` with that dependency name changed, recorded 2026-09-30 on WSL2 Ubuntu 24.04.1. The full output is `fixtures/ldd-wsl-ubuntu-24.04.txt`, recovered from commit `89319ac2`. This was not a Chromium run. Doctor checks installed Playwright headless shells on Linux and names `install-deps chromium-headless-shell` for missing libraries. A missing shell or a failed probe is `unsure`, not evidence that the libraries load. The live Linux checks remain open in #135.
