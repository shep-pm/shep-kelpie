# Coding standards

Read when reviewing a change. Mechanical rules live in CI and tests; these are the judgement calls they cannot make.

- Field lifecycle. For every field a change adds to the state file or a work item, list each path that sets it and each path that clears it, and name the scenario where it is left set when it should not be (a round that ends with no push, a withdrawn ruling, a new pass, a restart, main moving). A field with a stale scenario is a defect.
- A wrong ruling is a defect. A ruling raised without cause, or an `auto` merge held without cause, costs the maintainer's attention. It is never a safe over-flag.
- Restart. Each new phase or step transition is checked against a runner restarting between its steps, including anything kept only in memory.
- Stale prose. A change in behaviour searches comments, error strings, prompt text, README and the design log for the old wording, and fixes it in the same commit.
- Every start state. A new wait, retry or answer path is checked against the start path (worktree prepare, the ledger, a restart, a drain, the next look, the status line, the clock) and against every state it can start from.
- One concept, one source. When several consumers or paths act on one concept, such as a diff base, a ruling's number or a header, they derive it from one place, or the change checks every one of them.
- Worker-writable is hostile. Anything kelpie reads from or writes to a place a worker can write treats it as hostile: hard links, FIFOs, symlinks, an untrusted sender. A secret is checked where it is first read, and a guard that drops input says what it no longer sees.
- Test hygiene. A test waits on observable state, never a sleep. It takes a counter's baseline before the action it measures, it is shown red once so it cannot pass vacuously, and a test of a persisted field also reads a record from the older version.
- Crate layering. A crate uses only what is below or beside it in ADR 0015's map. Its manifest never names a crate that depends on it, not even as a dev-dependency, and a test rig part goes in the lowest crate that can hold it, behind that crate's `test-support` feature.
- Harness parity. A change that gives one harness adapter a capability, such as an `Agents` method, a sandbox rule, a call setting or a recovery, gives it to pi in the same pull request, or names the open pi issue that does. Codex follows the same way, and its issue may wait on pi's. An `Agents` default that refuses, or a `refuse_unsupported` line, is a gap with an issue, never the design. `docs/parity.toml` records what every provider in each category can do, harnesses, review bots, webhooks and gateways, and `crates/core/src/parity/mod.rs` fails CI on a provider, branch or refusal it does not cover.
- Building the big structs. `AgentCall`, `Finding`, `WorkItem`, `Ruling` and `Ask` are built with their `new` and `..`, never a full literal, so a new field is an edit to its definition and `new` alone. A field a caller must decide takes a `new` parameter or is set at the call site beside `..`, and `new` defaults only what has a sensible default.
- Live settings. A setting applies at the next reread, with no restart, whether it sits in a project's table or the dog's own `[kelpie]` section, so `shep set`, lookout and a GUI can change it in place. A reread that fails keeps the old value and says why. A key that truly cannot apply live, such as a security check read once at start, is named in `status` and `doctor` as waiting for a restart. One that waits for a restart silently, or only says so in a doc comment, is a defect.
- Module layout. A module with children lives in `foo/mod.rs`, never `foo.rs` beside a `foo/` folder; a leaf module is a single `foo.rs`. `clippy::self_named_module_files` is denied in `Cargo.toml`.
- Fewer settings. A settings key is a fact kelpie cannot detect or a safety limit. A judgement, such as how much of something is enough, which agent to pick or when to wait, goes to the project manager, or to a default kelpie derives. A pull request that adds a key says why neither can decide it: `scripts/settings-count.py` fails when the keys in `settings.example.toml` or `kelpie-settings.example.toml` pass their line in `.github/settings-baseline.txt`, and `--update` rewrites the baseline so the new count shows in the diff.
